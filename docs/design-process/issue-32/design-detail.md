# #32 の詳細設計: 全体の設計の 8 本と用語集を、どの節をどの順で直すかまで決める

設計文書 [design.md](design.md) の「構成要素」「指摘 11 件の扱い」「R1〜R15 の扱い」を、ファイルと節の粒度へ下ろした文書である。

この変更はコードを持たない。直す対象は全体の設計の文書（`docs/design/`）と用語集で、コードの「関数」に当たる単位は文書の**節**（`##`・`###`・`####` の見出しの下）である。この文書では次のように読み替える。

| テンプレートの語 | この文書での意味 |
| --- | --- |
| ファイル | 直す・新しく作る Markdown と JSON のファイル |
| クラスまたはモジュール | 1 本の設計の文書 |
| メソッドと最上位の関数 | 文書の節。足す節・書き換える節・移す節を並べる |
| 関数の仕様 | コードの関数が無いため省く。節ごとの中身は設計文書の 2 つの扱いの表が正本で、ここでは置き場だけを決める |
| 異常系の処理 | 実装の段の作業（節の移し・子の課題の本文への追記・用語集の作り直し）が失敗したときの扱い |

設計文書が持つ中身（正しい状態の文・順序図・決定の理由）は、ここへコピーしない。ここが持つのは、**どのファイルのどの節へ置くか・どの順で直すか・行数の見込み・失敗したときの扱い**だけである。

## 並行と排他

| 同時に走りうる処理 | 共有する資源 | 排他の取り方 | 冪等性と中断からの再開 |
| --- | --- | --- | --- |
| 他の子の課題の設計（`issues/issue-<番号>-design.md`）が `platform.md#進行表の-db` などの節を指して書かれている | 移す節の見出し（リンクの行き先） | 排他は取らない。platform.md に `## 状態の置き場` の見出しと移した節の対応の表を残し、古いリンクから data.md の節へたどれるようにする。実装の段で `gh pr list --state open` の設計 PR の差分を `platform.md#` で検索し、移した節を指す PR があれば、実装の PR の本文に番号と新しい行き先を並べる | 対応の表は何度書いても同じ |
| 他の変更が同じ時期に `docs/design/` の同じ文書を直す | 文書の行と決定の番号 | git のマージで食い違いを検出する。決定の番号は実装の前に「異常系の処理」の採番の照らしを打ち直す | 食い違えばこのブランチの側で取り込み直し、段 9 の照らしを打ち直す |
| 子の課題の本文への追記と、他の人・他のスプリントの同じ本文の編集 | 課題の本文 | 読んだ時刻（`updatedAt`）を書く直前に照らす楽観の排他。GitHub は本文の条件つきの書き込みを持たないため、照らしから書き込みまでの短い隙間は残る | 追記は `## #32 から渡された欠け` の節を置き換える形にし、何度打っても節は 1 つになる。途中で止まっても、残りの課題から打ち直せる |
| 実装の段の作業の中断 | 作業のブランチ | 1 つのブランチを 1 つの作業だけが触る（worktree の決まり） | 段 1〜9 はファイルの書き換えだけで、どの段の後でも打ち直せる。段 10 は上の行のとおり冪等 |

## 異常系の処理

コードの関数が無いため、1 列目には実装の段の作業を置く。

| 関数 | 失敗 | 原因 | 検出する場所 | 扱い | 利用者に見える出力と終了コード | 後始末と再実行の可否 |
| --- | --- | --- | --- | --- | --- | --- |
| 節の移し（platform.md → data.md） | 移した節を指すリンクの行き先が無くなる | 他の文書が `platform.md#進行表の-db` などの節を指している | 下の「処理の手順」の 4 のリンクの照らし | 止める。行き先を data.md の節へ書き換えてから次へ進む | 照らしのコマンドが行き先の無いリンクを 1 行ずつ出す | 書き換えて照らし直す。何度でもやり直せる |
| 節の移し（platform.md → data.md） | 移した後の文書が 1,000 行を超える | 書き足しの見込みが外れた | `wc -l docs/design/*.md` | 止める。文書をさらに分ける判断は設計の変更になるため、設計承認ゲートへ戻す（決定 2 の範囲の外） | `wc -l` の 1,001 行以上の行 | 書き足しを戻さずに止め、設計を直してから続ける |
| 各文書の書き換え | 同じ事柄の答えが 2 つの文書に文で残る | 正本でない文書の文を消し忘れた | 下の「単体テストの観点」の正本の照らし | 止める。正本でない側をリンクへ替える | 照らしの検索が 2 つの文書に当たる | 直して照らし直す |
| 決定の番号の採番 | 書き先の番号が既に使われている | 設計文書を書いた後に他の変更が `docs/design/` に決定を足した | 設計文書の「決定の記録」の冒頭の `grep` を実装の前に打ち直す | 止める。番号を変えると設計文書の書き先と食い違うため、設計文書の書き先を直して設計承認ゲートへ戻す | `grep` の結果に書き先の番号が出る | 採番を直すまで決定の節を足さない |
| 用語集の作り直し（`glossary.py render`） | 生成物が正本と合わない・壊れた JSON を読めない | 手で `glossary.md` を直した・JSON の書き損じ | `glossary.py check --file` と `render` の終了コード | 止める | `glossary.py` の 0 以外の終了コードと指摘の行 | `glossary.json` を直して `render` を打ち直す。生成物は何度作り直しても同じ |
| 子の課題の本文への追記（`gh issue edit`） | 追記が他の人の同じ時刻の編集を上書きする | 本文を読んでから書くまでの間に、別の人か別のスプリントが本文を直した | 書く直前に `gh issue view --json body,updatedAt` を読み直し、読んだ時刻と比べる | 再試行（読み直して、もう一度追記を組む）。2 回続けて食い違ったら止める | 止めたときは課題の番号と理由を実装の PR の本文の「残したこと」に書く | 上の「並行と排他」のとおり、同じ見出しの節を置き換えるため何度打っても 1 つになる |
| 子の課題の本文への追記（`gh issue edit`） | 渡す先の課題が閉じている・番号が無い | 設計文書を書いた後に閉じられた | `gh issue view --json state` | 止める。渡す先を変えるのは要求の前提 4 の読み替えで、人へ残す判断のため人へ戻す | 課題の番号と状態を報告に書く | 他の渡す先の追記は続けてよい。閉じた 1 件だけを残す |
| 子の課題の本文への追記（`gh issue edit`） | GitHub の API が失敗する | ネットワークの誤り・レート制限・権限 | `gh` の終了コード | 再試行（間を空けて 3 回まで）。超えたら止める | `gh` の誤りの文と終了コード | 追記は同じ見出しの節の置き換えで冪等のため、再実行してよい |

## 処理の手順

直す順は、リンクの行き先を先に作り、指す側を後に直す順にする。行き先の無いリンクが途中の版に残る時間を短くし、照らしを各段の後で打てるようにするためである。

| 関数 | 条件の組み合わせ | 結果 |
| --- | --- | --- |
| 1. data.md を作る | 常に | platform.md の「状態の置き場」の下の 6 つの節を、見出しの深さを 1 段上げて data.md へ移す（`##` 置き場の分け方 … CRUD 図）。platform.md には `## 状態の置き場` の見出しと、data.md を指す 1 段落と、移した節の対応の表を残す |
| 1. data.md を作る | 移した節の中の `(#…)` のリンクの行き先が data.md に移った節 | data.md の中のリンクのままにする（`#表と鍵` など） |
| 1. data.md を作る | 移した節の中の `(#…)` のリンクの行き先が platform.md に残る節 | `platform.md#…` へ書き換える（`#未確認のまま残ること`・`#費用`・決定の節など） |
| 2. data.md を直す | 常に | 設計文書の「データ構造」と、指摘 7〜9・11 と R1・R3・R8・R9・R13 の行を、上の「クラスと関数の構造」の data.md の行の節へ書く |
| 3. platform.md を直す | 常に | arc42 の 8 章の行・環境の値の受け方・検査・非機能・外部の調査・言語と書き方の決まりの節・決定 95〜99・決定 140 を書く。`AGENTS.md` の細則の行を、言語と書き方の決まりの節へのリンクに替える。platform.md に残る節の中の `(#表と鍵)`・`(#形の版と移し方)`・`(#用意の手順)` を `data.md#…` へ書き換える |
| 4. リンクを照らす | 1〜3 の後 | `docs/design/` の中の `platform.md#` のリンクをすべて並べ、行き先の見出しが platform.md にあるかを照らす。無ければ data.md の節へ書き換える（api.md の 2 行と overview.md・execution.md の `#状態の置き場` の行） |
| 5. execution.md・api.md・overview.md を直す | 常に | 扱いの表の各行を、上の「クラスと関数の構造」の節へ書く。順は execution.md → api.md → overview.md（overview.md の不変条件とテスト設計が execution.md と data.md の節を指すため） |
| 6. detail.md・screens.md を直す | 常に | 受け持つ子の表・クラス図・境界の検査の対象・メンバーの見せ方・札・外部の調査の畳みを書く |
| 6. detail.md・screens.md を直す | 畳んだ STD21・STD25・STD28・LIB45 が本文に残っている | 畳んだ先の番号へ書き換える。`grep -rn 'STD2[158]\|LIB45' docs/design/` が 0 件になるまで |
| 7. decisions.md を直す | 常に | 決定の置き場の表に 100〜119・120〜139・140〜159 の行を足し、決定 1・6・7・9 と決定 3 の比べた候補を書く |
| 8. 用語集を作り直す | 常に | `glossary.json` の「資格情報の差し替え」の出所を data.md へ替え、`glossary.py render` で `glossary.md` を作り直す |
| 9. 照らす | 1〜8 の後 | 下の「単体テストの観点」の検索と検査をすべて打つ。どれかが当たれば該当の段へ戻る |
| 10. 子の課題の本文へ追記する | 1〜9 がすべて通った後 | 渡す先 12 件へ、設計文書の「子の課題へ渡す欠け」の行を追記する。リンクは直した後の `docs/design/` の節を指す（9 が通る前に追記すると、行き先の無いリンクを課題へ書くことがある） |
| 10. 子の課題の本文へ追記する | 本文に `## #32 から渡された欠け` の節が既にある | その節を置き換える（足さない） |

- 繰り返しの終わる条件: 段 9 の照らしがすべて 0 件になったとき。段 10 は渡す先 12 件をすべて書き終えたとき（閉じた課題は「異常系の処理」のとおり残して報告する）
- 計算量の注意: 無し。文書は 8 本・合わせて 5,000 行ほどで、検索は 1 回 1 秒に収まる

## 単体テストの観点

コードのテストは無い。設計文書の「テスト設計」の受け入れ条件を、段 9 で打つ検索と検査へ下ろす。

| 関数 | 正常 | 境界値 | 異常 |
| --- | --- | --- | --- |
| 節の移し（platform.md → data.md） | `grep -rnoE '(platform\|data)\.md#[^) ]+' docs/design/` の各リンクの行き先の見出しがある | 移した節の中から platform.md に残る節を指すリンク（`#未確認のまま残ること`・`#費用`）が `platform.md#…` になっている | 行き先の無いリンクが 1 件でもあると落ちる |
| 節の移し（platform.md → data.md） | `wc -l docs/design/*.md` がすべて 1,000 行以下 | execution.md が 950 行以下（上の見込みの余り） | 1,001 行以上の文書があると落ちる |
| 各文書の書き換え | 扱いの表の各行の正本の節に正しい状態の文があり、ほかの文書はリンクだけ | 「人だけか」の区分（指摘 2）と状態の 3 つ（R2）が execution.md にだけ表として載る | 正本でない文書に別の答えの文が残ると落ちる |
| 各文書の書き換え | `grep -n '詳細設計' docs/design/*.md` の当たりが、受け持つ子の番号か detail.md の節を指す | detail.md 自身の見出しの当たりは除く | 行き先の無い「詳細設計が持つ」が 1 件でもあると落ちる |
| 決定の番号の採番 | 決定の書き先の番号がそれぞれ 1 つの文書の見出しにだけある | 100〜103・120・140 が decisions.md の置き場の表の範囲に入る | 同じ番号が 2 つの文書の見出しにあると落ちる |
| 外部の調査の畳み | `grep -rn 'STD2[158]\|LIB45' docs/design/` が 0 件 | api.md の決定 51 と detail.md の再利用の表の LIB40 | 畳んだ番号の参照が残ると落ちる |
| 用語集の作り直し | `glossary.py check --file` を直した文書と要求のコピーへ打って当たりが 0 件 | `glossary.md` が `render` の出力と同じ | 当たりが 1 件でもある・生成物が古いと落ちる |
| 実際のインフラの値 | `grep -nE '(^\|[^0-9-])[0-9]{12}([^0-9-]\|$)\|arn:aws' docs/design/*.md` が `123456789012` だけ | data.md（新設）も検索に入る | 作り物でない 12 桁か ARN があると落ちる |
| 子の課題の本文への追記 | 渡す先 12 件の本文に `## #32 から渡された欠け` の節が 1 つずつあり、各行にリンクがある | 打ち直した課題でも節が 1 つ | リンクの無い行・節が 2 つある課題があると落ちる |
| 子の課題の本文への追記 | 追記した課題の番号が実装の PR の本文に並ぶ | 閉じていた課題は「残したこと」に並ぶ | 本文の番号と追記した課題が食い違うと落ちる |
