# 端末のデータとそろえ方

## 概要

画面が端末に置くデータと、つながったときに端末とサーバーの状態を合わせる処理（そろえ方）の仕様である。`apps/web/src/offline/` に実装している。

- API のレスポンス・まだ送れていない操作・ログインのキャッシュなどを、取り出せない AES-GCM のキーで 1 件ごとに暗号化し、IndexedDB に置く
- 操作は 3 つの区分（キャッシュして送る・確定待ち・つながってから押す）で扱う。確定待ちは、サーバーが今の状態と押した時点のバージョンを照合して成功を返したときだけ確定と出す（全体の設計の不変条件 I4）
- 送れないと決まった操作は消さずに保留の件として残す。データベースを消すときに本人が破棄を確認していない操作は、別の IndexedDB へ隔離し、同じ利用者のサインインで戻す
- そろえ方は、開いた・つながった・見えるようになった・30 秒ごとに、段 1〜5 を通す

**今の状態**: この層は、本番の起動ではまだ使っていない。本番の起動は端末のデータベースを開かず、写し・送る列・そろえ方を動かさない。使い始めるのは、ログインのキャッシュの保存先を端末のデータベースへ切り替えるとき（#4 の「サインインを確定する」呼び出しと同じリリース。[#196](https://github.com/devbasex/nd-factory/issues/196)）である。今はダミーの mode（[画面の基盤](screen-foundation.md#ダミーのクライアント)）と単体テストだけが使う。本番のそろえ方の読み出し（`apps/web/src/app/device.ts` の `PENDING_READERS`）は、操作の形が決まるまでどれも一時の失敗を返し、何も消さない。

## 用語

語の意味は [用語集](../glossary.md) に従う（写し・送る列・保留の件・隔離・ログインのキャッシュ・ログインキャッシュ行・連携ログイン・そろえ方の回・錠・つながってから押す・確定待ち・キャッシュして送る）。用語集に無い語のうち、この文書で使うものは次のとおりである。

| 語 | 意味 |
| --- | --- |
| 答えの ID | 送る列のどの件も持つ、件を引くための識別子（`idempotencyKey`。UUID v7）。冪等キーを受ける操作では API の冪等キーとしても送る |
| 先映し | キャッシュして送る操作を押した時点で、サーバーの結果を待たずに写しへ反映すること |
| 重ね直し | サーバーのレスポンスで写しを置き換えるときに、送る列に残るキャッシュして送るの件を、押した順にもう一度写しへ反映すること |
| 見られる対象の記録 | 最後に読めた見られるプロジェクトと席を持つチームの並び、表示を保留する対象の並び（保存先 `authz`） |
| 途中の記録 | サインアウトと連携ログインの解除を、タブを閉じた後も続けるために置く 2 つの値。サインアウトの証（`sessions.delete` に送る access token）と、外しのキャッシュ（今のセッションを発行した連携ログインを解除する `logins.delete` のアイテム） |
| 途中のフラグ | サインアウトの途中のフラグと、連携ログインの解除の途中のフラグ（どちらも `localStorage`。#4 が置く） |
| セッションの指紋 | `sub` と `origin_jti` をつないだ値の SHA-256 |
| 送り始めた印 | 件を 1 度でも送り始めたか（`sendStarted`）。真の件はサーバーで確定している場合がある |

## コンテキスト

用語集のプラットフォーム（`platform`）のコンテキストに属する。サーバーとは、スキーマの正本の操作の形だけでやり取りする。リクエストの本文はアイテムの配列で、レスポンスは同じ順のアイテムの結果（成功か、ステータス番号と理由のコード）の配列である（[API の文書の本文は配列](../design/api.md#本文は配列)）。送る列の 1 件は、このアイテム 1 件に当たる。どの集約も端末の中だけにあり、サーバーの集約を書き換えない。

## 背景

| 選択 | 理由 |
| --- | --- |
| IndexedDB は idb で包み、暗号化は Web Crypto を直に呼ぶ小さな層で持つ | 暗号化を 1 か所に閉じるため |
| ログインのキャッシュは `userStore` を差し替えて置き、`set` はメモリに留める | 置く項目を決まったものだけにし、access token と ID token を端末に置かないため |
| 操作の 3 つの区分は画面の側の表に持ち、全操作に区分があることをテストで確かめる | 書き込みの操作の扱いを画面の都合で決めるため |
| 送れない件は保留にし、データベースを消すときに残る件は別の IndexedDB へ隔離する | 利用者が入力した操作を、確認なしに失わないため |
| 平文の列には HMAC の値だけを置き、ID を置かない | 端末の IndexedDB を直に読んでも、どの対象・プロジェクト・利用者のデータか分からないようにするため（同じ配信元でスクリプトを実行できる人には効かない） |

## 対象範囲

含む: 端末のデータベースと隔離の IndexedDB、写し・送る列・保留の件・ログインのキャッシュ・途中の記録・送信の待機・見られる対象の記録の読み書き、そろえ方の段 1〜5、#4 が呼ぶ書き込みと削除の関数。

含まない: API と Cognito を呼ぶサインインとサインアウトの段・途中のフラグ・タブ間の通知（[#4](https://github.com/devbasex/nd-factory/issues/4)）、Web Push（[#8](https://github.com/devbasex/nd-factory/issues/8)）、操作の形と読み出しの中身（機能の画面 [#28](https://github.com/devbasex/nd-factory/issues/28) と操作を持つ課題）。

## 仕様

### 集約

| 集約 | 根 | 主な値 |
| --- | --- | --- |
| 端末のキャッシュ | 写しの 1 件 | 種類・対象・含むプロジェクトの集合・受け取った時刻・暗号文 |
| 送る列（保留の件を含む） | 送るアイテムの 1 件 | 区分・操作の名前・対象・入力・答えの ID・照合の値・押した時刻・送る順の番号・送った時刻 |
| ログインのキャッシュ | 1 件 | 利用者・セッションの指紋・refresh token の期限・暗号文 |

| 途中の記録 | サインアウトの証 1 件と外しのキャッシュ 1 件 | 種類・セッションの指紋・暗号文 |

### 常に成り立つ条件

番号はコードの注釈が引く番号である。

| # | 条件 |
| --- | --- |
| I4 | 確定待ちは、つながっていない端末では送らず確定と出さない。確定と出すのは、送ったアイテムの結果が成功のときだけである。HTTP 200 でもアイテムが失敗なら確定と出さない |
| IW1 | API のレスポンス・送る操作・refresh token・途中の記録・待機の期限・見られる対象の記録は、1 件ごとに暗号化して IndexedDB に置く。Service Worker の保存先に API のレスポンスを置かない |
| IW2 | 受け取ってから 14 日を過ぎた写しは画面に出さない。読むときに除き、開いたときに消す |
| IW3 | 同じ対象への、まだ送り始めていない確定待ちは 1 件だけである。後から押したら置き換える。送り始めた件は置き換えず、後から押した方を別の件として後ろに足す |
| IW4 | つながってから押す操作は、つながっていない端末で送る列に入らない |
| IW5 | 見られるプロジェクトの一覧（`projects.list`）を全ページ読み終える前に、送る列を送らず、写しを消さず、件を保留に移さない |
| IW6 | サインアウトの後に、その利用者の写し・ログインのキャッシュ・途中の記録・キーが残らない。送る列と保留の件は、本人が破棄を確認した件が残らず、確認していない件は隔離にだけ残る |
| IW7 | データベースのデータは、持ち主として記した 1 人の利用者のものだけである。ログインキャッシュ行の利用者が持ち主と違えば、写しを描かず送る列を送らない。隔離の件は、その持ち主のサインインまで読まず、送らず、件数もほかの利用者に出さない |
| IW8 | 送った結果で消すのは、送ったときと同じ答えの ID の 1 件だけである |
| IW9 | 押してから 24 時間を過ぎた確定待ちは送らない |
| IW10 | refresh token の期限（サインインから 30 日）を過ぎたログインキャッシュ行と、取り直しを Cognito が `invalid_grant` で拒んだ行を残さない。消すのはその行だけで、写しと送る列と保留の件は消さない |
| IW11 | 写しにするのは「写しにする種類の表」の種類だけである。表に無い種類の書き込みは捨てる |
| IW12 | 送る列は押した順に送る。一時の失敗を受けたら、その回の段 2 を止め、残りを次の回へ回す |
| IW13 | 送る列と保留の件を端末が消すのは、サーバーがその件の結果を返したときと、利用者がその件を消す操作（同じ対象の置き換え・取り下げ・破棄の確認・サインアウトの確認）をしたときだけである。版の上げ・復号の失敗・権限の喪失・期限・持ち主の交代では消さず、保留に移すか隔離する |

### 写しにする種類の表

`snapshot-kinds.ts` の 1 か所に持つ。含むプロジェクトの集合は、中身の `project_id` の項目から集める。

| 種類 | 写しにする操作 | 件数の上限 |
| --- | --- | --- |
| `organizers` | `organizers.list`・`organizers.get` | — |
| `organizer-messages` | `organizer_messages.list` | 200 |
| `approvals-list` | `approvals.list`・`questions.list` | — |
| `waiting-counts` | `waiting_counts.get` | — |
| `sprint-list` | `sprints.list` | 50 |
| `sprint` | `sprints.get`・`lanes.list`・`progress_events.list`（一覧 `sprint-list` の記録より古い詳細は採らない） | — |
| `approval` | `approvals.get` | — |
| `question` | `questions.get` | — |
| `notices` | `notices.list` | 100 |
| `places` | 段 1 が `teams.list` と `projects.list` から作る場所の一覧 | — |
| `self` | `users.get` | — |
| `last-project`・`last-conversation`・`section` | 画面の状態（最後に開いたプロジェクト・最後に開いた会話・畳む節の開閉） | — |

- 上限を超える項目は後ろ（古い方）から落とす。表に無い操作のレスポンスは、つながっているときだけ読み、写しにしない
- 写しはサーバーのレスポンスで丸ごと置き換え、送る列に残るキャッシュして送るの件を重ね直す
- 写しを置き換えるときは、新旧を読み出しの通し番号（`fetchSeq`）で比べ、古いレスポンスで新しい写しを上書きしない。消した対象には削除の印を、全ページ読めた一覧には返った対象の記録を残す
- 場所の一覧は、プロジェクトが 0 件の席を持つチームも入れる。`teams.list` だけを読めなかった回は、`projects.list` の結果のプロジェクトとそのチームだけで作る

### 操作の 3 つの区分

`operation-classes.ts` の表に持つ。表に無い操作は、つながってから押すとして扱う。冪等キーを受けるかは操作の表（スキーマの正本）が正で、ここには写さない。

| 区分 | 操作 |
| --- | --- |
| キャッシュして送る | `users.update`・`notices.mark_read`・`organizer_messages.create`・`organizer_messages.withdraw` |
| 確定待ち | `approvals.answer`（照合の値は `version` と `material_digest`）・`questions.answer`・`sprints.cancel`・`project_transfers.create`・`project_transfers.accept`・`project_transfers.delete`・`projects.close`（照合の値は `version`） |
| つながってから押す | 上のほかのすべての書き込みの操作（サインイン・連携ログイン・チーム・席・招待・プロジェクト・実行の設定・通知先・委任・オーガナイザーの作成と終了など） |

- キャッシュして送るの操作は、冪等キーを受けないときに送り直してよいか（`organizer_messages.create` だけが偽）と、利用者が入力した文を持つか（`users.update`・`organizer_messages.create` が真）を持つ
- 確定待ちは、照合の値がそろわなければ保存しない（`MissingCheckError`）。`version` は整数、`material_digest` は空でない文字列である。画面は対象を読み直すよう求める

### 送る列の 1 件

暗号文の中に、操作の名前・対象の ID・プロジェクトの ID・入力・照合の値・割り当ての受け入れ先（受け入れだけ）・答えの ID・押した時刻・API の時刻で数えた押した時刻の下限（`pressedFloor`）・送る順の番号・送り始めた印・送った時刻を置く。拒まれて保留に移した件はアイテムの結果を、会話への送信が成功した件は返った項目の ID を足す。

件を足すときは、送る順の番号を Web Locks の錠 `nd-outbox` の中で取り、後から押した件の番号が先に押した件より前にならないようにする。

### 保留の件

送らないと決まり結果を受けていない件と、サーバーが拒んで入力を残す件である。送る列の行を暗号文のまま移すため、読めない件も失わない（拒まれた件だけは、結果を足して暗号化し直す）。理由は次の 8 つである。

| 理由（`holdReason`） | 保留にする時機 |
| --- | --- |
| `unmigrated` | 版の上げで新しい形に移せない |
| `unreadable` | 復号できない |
| `revoked` | 段 1・段 5 で、プロジェクトを見る権限が無くなったと確かめた |
| `transfer-unavailable` | 受け入れ先のチームの受け入れ待ちの一覧が 403・404 か、一覧に移行が無い（送り始めた印が偽） |
| `expired` | 押してから 24 時間を過ぎたか、24 時間以内と確かめられない（送り始めた印が偽） |
| `restored` | 隔離から戻した確定待ち（送り始めた印が偽） |
| `unknown-result` | 送ったかもしれない件を自動で送り直さないと決めた。送った件が 422 か、再送の 403・404 を受けた |
| `rejected` | 恒久の拒否を受けた確定待ちと、入力した文を持つキャッシュして送るの件 |

- 保留の件は、利用者が件ごとの「破棄する」を確認のダイアログで確定したときだけ消す。期限と版の上げでは消さず、端末は送り直さない
- 1 件でもあれば、オフラインの帯の位置に件数と「内容を確認する」を出す。件数は、保留の件と、サインインしている利用者が持ち主の隔離の読めない件の合計である
- 一覧に出す項目は `visibleFieldsOf` が決める。理由と「破棄する」は常に出す。操作の名前と押した時刻は復号できたときだけ出し、読めなければ「内容を読めません」と区分を出す。入力・対象・照合の値・結果は、対象を今の権限で見られると確かめられたときだけ出す。自分の設定の操作（`users.update`・`notices.mark_read`）は常に見られる。記録が無いか確かめられなければ見られないとして扱う
- 保留の件は後続の件の送信を止めない

### 隔離

データベースを消す必要があるのに持ち主が破棄を確認していない件を、別の IndexedDB `nd-quarantine` へ移して残す。持ち主ごとの行に `ownerTag`・`key`・`tagKey`・移し終えた版を置き、件は `ownerTag` を加えて暗号文のまま置く。写し・ログインのキャッシュ・途中の記録は移さない。

| 時機 | 扱い |
| --- | --- |
| 持ち主と違う利用者でサインインを確定する | 送る列と保留の件をすべて隔離してから、データベースを消して作り直す |
| サインアウト（#4 の 2. と 5. の段） | このサインアウトの確認の記録にある件は消し、ほかの件は隔離する。記録が無いか、記録のタグがサインアウトの ID の HMAC と一致しなければ、すべて隔離する |
| 同じ利用者のサインインを確定する | 持ち主の行の `tagKey` で利用者の ID を HMAC にし、一致する行の件を今のキーで暗号化し直して戻す。読めない件は隔離に残す |

戻し先は次のとおりである。再びサインインしただけでは、隔離の前に押した確定待ちを送らない。

| 隔離していた件 | 戻し先 |
| --- | --- |
| 確定待ちで、送り始めた印が偽 | 保留の件（`restored`） |
| 確定待ちで、送り始めた印が真 | 保留の件（`unknown-result`） |
| キャッシュして送る | 送る列 |
| 保留の件 | 保留の件（理由は変えない） |

隔離は、キーの行に `switching` を書く → 件を隔離の側へ書く → 元のデータベースを消す、の順に行う。起動で `switching` が残っていれば、元のデータベースを正として、元にも残る件の複製を隔離の側から消してから `switching` を外す（`rollbackQuarantine`）。隔離の書き込みが失敗したら、元のデータベースを消さずに失敗を返す。

### ログインのキャッシュと #4 との分担

ログインのキャッシュの保存（`createLoginStore`）は `oidc-client-ts` の `userStore` として渡す。`set` はメモリに留めるだけで、IndexedDB へは #4 が呼ぶ 2 つの関数だけが書く。access token と ID token は置かない。

| 関数 | 呼ぶ者と条件 | 振る舞い |
| --- | --- | --- |
| `confirmSignin(userId)` | #4 が、`sessions.create` の成功と途中のフラグ・token の照合の後に、サインインの錠を持って呼ぶ | 利用者が持ち主と違えば隔離してデータベースを作り直し、隔離した同じ利用者の件を戻してから、ログインキャッシュ行を書く |
| `discardPendingExchange()` | #4 が、`sessions.create` の失敗か照合の外れで呼ぶ | メモリに留めた交換の結果を捨てる |
| `readFingerprintTag()` | #4 が取り直しの前に呼ぶ | 今の行の `fingerprintTag` を返す |
| `writeRefreshed(fingerprintTag)` | #4 が取り直しの成功の後に呼ぶ | 渡したタグ・今の行・持ち主が合い、途中のフラグが無いときだけ書く。合わなければ `discarded` |
| `deleteLoginRow(fingerprintTag)` | #4 が `invalid_grant` を受けた後に呼ぶ | 今の行のタグが同じときだけ消す。違えば `kept` |
| `purgeExpiredLogin(nowMs)` | 起動 | 期限を過ぎた行だけを消す |

refresh token の期限は、token の `auth_time` から 30 日である。行の中身は `refresh_token`・利用者の ID・`profile.sub`・`scope`・`token_type`・期限である。`userTag` は `sessions.create` が返すアプリの利用者の ID から作り、Cognito の `sub` からは作らない。

途中の記録の保存（`createPendingStore`）は、#4 だけが錠を持ったまま呼ぶ。復号できない記録は消さずに `unreadable` を返す。サインアウトの片付けは、`recordDiscardConfirmation`（破棄を確認した件をサインアウトの ID と結び付けて書く）→ `settleForSignout`（2. の段）→ `deleteDeviceData`（5. の段。隔離し残した件があれば消さずに `failed`）の順に #4 が呼ぶ。`forgetDeviceMemory` は、復号した値とキーの参照をメモリから捨てる。

### そろえ方

#### 回の起動と排他

起動の元は、開いた・つながった・見えるようになった・30 秒ごとの 4 つである。同じ端末のどのタブでも、Web Locks の錠 `nd-sync` を `ifAvailable` で取れたときだけ回を通す。取れなければ何もしない。回を始める前に、持ち主がいること・途中のフラグが無いこと・つながっていることを確かめる。回の対象の件は段 1 の初めに決め、後から足された件は次の回へ回す。

#### 段 1〜5

| 段 | すること | 失敗したとき |
| --- | --- | --- |
| 1 | `projects.list` と `teams.list` を全ページ読み、見られなくなったプロジェクトの写しを消し、その送る列の件を保留（`revoked`）に移し、場所の一覧と見られる対象の記録を書き換える。受け入れの確定待ちがあれば、受け入れ先のチームごとに `project_transfers.list` を読む | `projects.list` の途中の失敗では何も消さず送らず、回を終える。`project_transfers.list` だけが一時の失敗なら、失効の反映は行い、段 2 の送信をしない |
| 2 | 送る列を押した順に 1 件ずつ、期限を確かめてから送り、結果を反映する。429 の待機の期限の間は送らない | 一時の失敗で段 2 を止め、残りを次の回へ回す |
| 3 | 見ている画面を読み直し、写しを置き換える | 前の写しを残し、「読み直せませんでした（時刻）」を出す |
| 4 | 承認待ちの一覧とオーガナイザーの一覧を読み直す | 同じ |
| 5 | 全ページ読めた一覧に返らなかった行を消す。アイテムの 404 を受けた対象は 1 件の写しを消し、そのプロジェクトの表示を保留して一覧を読み直す | 一覧の読み直しが一時の失敗なら、表示の保留を続けて次の回に任せる |

段 1〜5 の決まりの全体は、画面の文書の [つながったときのそろえ方](../design/screens.md#つながったときのそろえ方) にある。どの段も、各リクエストを送る前と、レスポンスを保存する前（同じトランザクションの中）に、利用者・セッション・途中のフラグを照合し、違えばレスポンスを捨てて回を止める。

#### 見られる対象の記録との照合

写しを画面に出すときは、写しを返した読み出しの通し番号と記録を `judgeVisibility` で照合する。上の行から順に当てる。

| 条件 | 判定 |
| --- | --- |
| 記録が無い | 出す |
| 対象が保留の並び（`denied`）にある | 保留（出さない。権限の喪失を確かめるまで） |
| チームの対象で、席を持つチームの並びが無いか、並びにある | 出す |
| チームの対象で、並びに無い | 通し番号がチームの一覧の読み出しより後なら出し、前なら消す |
| プロジェクトの対象で、見られるプロジェクトの並びにある | 出す |
| プロジェクトの対象で、所属の食い違いの並びにある | 通し番号が食い違いを記録した読み出しより後なら出し、前なら消す |
| そのほかのプロジェクトの対象 | 通し番号が最後のプロジェクトの一覧の読み出しより後なら出し、前なら消す |

記録を書き換える側は錠 `nd-authz` を排他で、画面へ反映する側は共有で取る。保留の並びに足すのは、段 2 の送信の 403・404、段 1 の受け入れ待ちの一覧の 403・404、段 5 のアイテムの 404 を受けたときである。プロジェクトをまたぐ写し（`approvals-list`・`waiting-counts`・`organizers`・`notices`）は、失効があれば丸ごと消す。

#### 段 2 の送る前の確かめ

送る直前に、錠の中で次を照合し、照合から送信の開始まで待ちを挟まない（`createApiSender`）。

| 照合 | 外れたとき |
| --- | --- |
| 途中のフラグが無く、キーの行とログインキャッシュ行があり、行の利用者が持ち主・回の利用者と同じで、指紋が回のセッションと同じ。送る token が回とメモリの token と同じ | 送らずに回を止める（`session`） |
| 件が送る列に残っている | 送らない（`gone`） |
| 確定待ちが押してから 24 時間以内 | 送らない（`deadline`） |
| API の時刻の読み出しから 60 秒以内（端末の時計と経過時間の両方で） | 送らない（`stale-time`） |

期限の判定（`checkDeadline`）は次のとおりである。確定待ちは、端末の時刻で 24 時間を過ぎたか、API の時刻が読めないか、API の時刻で `pressedFloor` から 23 時間 58 分を過ぎたら遅れとする。遅れた件は、送り始めた印が偽なら `expired`、真なら `unknown-result` の保留にする。送り始めた件の送り直しは、送った時刻から API の時刻で 23 時間以内に限る（冪等キーの保持期間 24 時間の 1 時間手前）。

#### 段 2 の結果ごとの扱い

判定は `classifyResult` が持つ。冪等キーを受けない操作は、キャッシュして送るで送り直してよいものだけを送り直す。

| 結果 | 扱い |
| --- | --- |
| HTTP 200 でアイテムが成功 | 送る列から消す。確定待ちは確定と出す。キャッシュして送るは先映しを残す。会話への送信は返った項目の ID を会話の写しに書く |
| アイテムが 409 `in_progress` | 一時の失敗。元の区分と冪等キーのまま、次の回で送り直す |
| アイテムが 422 | `unknown-result` の保留 |
| アイテムが 429 か 500 以上 | 一時の失敗 |
| 1 回目の送信のアイテムが 403・404 | 恒久の拒否。対象を保留の並びに足す |
| 再送のアイテムが 403・404 | `unknown-result` の保留。対象を保留の並びに足す |
| そのほかのアイテムの失敗（409・400 など） | 恒久の拒否 |
| リクエスト全体の 401 | 段 2 を止め、件を元のまま残す。#4 の 401 の扱いへ渡す |
| リクエスト全体の 429 | 段 2 を止め、待機の期限を全タブで共有する |
| リクエスト全体の 503・通信の失敗・API の形でない応答 | 一時の失敗 |

- 恒久の拒否は、確定待ちと入力した文を持つキャッシュして送るの件を `rejected` の保留に移す。入力を持たないキャッシュして送るの件は消す。キャッシュして送るの件は、その対象の写しを読み直して先映しを取り消す
- 一時の失敗は、送り直せる件なら元の区分のまま残して段 2 を止める。送り直せない件は `unknown-result` の保留に移す
- 会話への送信（`organizer_messages.create`）の後の取り下げは、成功が返した項目の ID で `organizer_messages.withdraw` を送る列に足す

#### 送信の待機と API の時刻

リクエスト全体の 429 を受けたら、次に段 2 を始めてよい時刻を `retryUntilFrom` で決め、保存先 `wait` の行 `retry` に置いて全タブで共有する。

| `Retry-After` | 待つ時刻 |
| --- | --- |
| 秒数 | 今から、その秒数の後 |
| 日時 | 応答の `Date` との差の長さだけ待つ（端末と API の時計のずれを持ち込まない）。`Date` が無ければその日時 |
| 無い・読めない | 既定の待ち。初回 60 秒、以後は倍にし、上限 15 分 |

API は今 `Retry-After` を画面へ公開していないため、既定の待ちを使う。最後に受けた API の応答の `Date` は、行 `api-time` に置き、確定待ちの期限の判定に使う。

### 版の上げ

データベースの版は今 1 で、移す中身は無い。版を上げるときは、`upgrade` で保存先と索引だけを足し、開いた後の `runMigrations` が保存先ごとに中身を移す。順は `keys`・`login`・`pending`・`outbox`・`held`・`wait`・`authz`・`snapshots`・`seq` で、キーの行・保留の件・番号は移さない。移せない送る列の件は `unmigrated` の保留に移す。復号と暗号化はトランザクションの外で済ませ、書くトランザクションで移行の記録・主キー・`iv` が読んだときのままかを確かめる。

## データ・設定

端末のデータベースは IndexedDB `nd-device`（版 1。利用者ごとに名前を分けない）で、9 つの保存先を持つ。

| 保存先 | 主キー | 平文の列 | 暗号文の中身 |
| --- | --- | --- | --- |
| `keys` | `id`（固定の `main`） | `key`（AES-GCM 256）・`tagKey`（HMAC-SHA-256。どちらも取り出せない）・`ownerTag`・`migrated`・`switching`・`discardConfirmed` | — |
| `snapshots` | `id`（種類と対象の ID の HMAC） | `kind`・`receivedAt`・`projectTags`（複数の値の索引） | レスポンスと読み出しの通し番号。削除の印の行と一覧の記録の行も置く |
| `outbox` | `answerTag`（答えの ID の HMAC） | `targetTag`（操作の名前と対象の ID の HMAC。一意でない索引）・`kind`（`queued` か `confirm`）・`projectTag` | 送る列の 1 件 |
| `held` | `answerTag` | 送る列と同じ列と `holdReason` | 送る列の 1 件（拒まれた件は結果を足す） |
| `login` | `id`（固定の `login`） | `userTag`・`fingerprintTag` | ログインのキャッシュ |
| `pending` | `id`（`signout-proof` か `unlink-item`） | `fingerprintTag` | 証の access token か `logins.delete` のアイテム |
| `wait` | `id`（`retry` か `api-time`） | — | 待機の期限と既定の待ちの長さ、または最後の `Date` |
| `authz` | `id`（固定の `authz`） | — | 見られる対象の記録 |
| `seq` | 番号の生成器 | — | 行を残さない。読み出しの通し番号を振る |

- 暗号文を置く保存先は、どれも 12 バイトの `iv` と暗号文 `data` を持つ。`iv` は暗号化のたびに新しい乱数を作る
- HMAC の値はどれも `tagKey` で作った 16 進の文字列である。HMAC の入力の各部分は `\u0000` でつなぐ
- 平文に置いてよいのは、画面の文書の [暗号化](../design/screens.md#暗号化) が決めたもの（種類・受け取った時刻・HMAC の値・固定の名前と真偽と版の番号・初期化ベクトル）だけである。プロジェクトの ID・対象の ID・利用者の ID・答えの ID・セッションの指紋・操作の名前と入力・押した時刻・期限は暗号文の中にだけ置く。平文の列を足すときは、先に画面の文書を改訂する
- 見られる対象の記録の中身は、世代の番号（`generation`）・見られるプロジェクトの並び（`allowedProjectIds`）とその一覧を読んだ通し番号（`listedSeq`）・所属の食い違いのプロジェクトの並びと通し番号（`mismatchProjectIds`・`mismatchSeq`）・席を持つチームの並びと通し番号（`allowedTeamIds`・`teamsSeq`）・保留する対象の並び（`denied`。ID と通し番号）である
- トランザクションの中では文字列とバイト列の比較だけを行う。HMAC と復号はトランザクションの外で済ませ、書く前に行の `iv` が読んだときのままかを確かめる。変わっていれば書かずに読み直す

隔離の IndexedDB は `nd-quarantine` である。使う Web Locks の錠は、`nd-factory`（サインインとサインアウト。#4 と共有）・`nd-sync`（そろえ方）・`nd-outbox`（送る順の番号）・`nd-authz`（見られる対象の記録）である。

| 相手 | やり取り |
| --- | --- |
| API | スキーマの正本の操作を、アイテム 1 件のリクエストとして送る。確定待ちは照合の値を、冪等キーを受ける操作は答えの ID を冪等キーとして送る。応答の `Date` を読む（CORS で公開済み） |
| #4（サインインとサインアウト） | 上の「ログインのキャッシュと #4 との分担」の関数を、起動の組み立ての `device` から呼ぶ |

## エラー処理

復号できないとき（キーが無いときも同じ）は、保存先ごとに次のとおり扱う。

| 保存先 | 扱い | 利用者に見えるもの |
| --- | --- | --- |
| 写し | 写しをすべて消し、オンラインなら読み直す | 出さない |
| 送る列 | 送らず、暗号文のまま `unreadable` の保留に移す。キーの行が無く持ち主を確かめられなければ、持ち主の分からない隔離に移す | 保留の件として件数と「内容を読めません」 |
| 保留の件 | 消さずに残す | 「内容を読めません」と理由 |
| 隔離 | 戻さずに、元のキーの行と版と一緒に残す | 持ち主に、保留の件と合わせた件数と「内容を読めません」 |
| ログインのキャッシュ | 読んだときのままの行だけを消し、行が無いのと同じに返す。行の利用者が持ち主と合わないときも同じ | 呼び出し元が決める（本番の起動につなぐのは #196） |
| 途中の記録 | 消さずに `unreadable` を返す | #4 が決める |
| 送信の待機 | 待機が無いものとして扱う。次の 429 で既定の待ちの初回から数え直す | 出さない |
| 見られる対象の記録 | 照合した書き込みの準備（`prepareGuard`）が `UnreadableError` を投げ、その回は失敗としてログに残して終わる | 出さない |

そのほかの失敗は次のとおりである。

| 場面 | 扱い |
| --- | --- |
| 端末のデータベースを開けない（非公開ブラウズ・容量） | 端末のデータを使わずに続ける |
| ほかのタブがデータベースを消すか版を上げる（`versionchange`） | 接続を閉じ、メモリの値を捨てる |
| 件を足す前に別のタブでセッションが替わった | `SessionChangedError` を投げ、保存の失敗と分けて扱う |
| 照合の値がそろわない確定待ち | 保存しない（`MissingCheckError`） |
| 隔離の書き込みの失敗 | 元のデータベースを消さずに失敗を返す |

## セキュリティ

- キーは `extractable` を偽にして作り、生の値を扱わない。`CryptoKey` は構造化複製で IndexedDB に置く
- 平文の列に ID を置かず、HMAC の値だけを置く。端末の IndexedDB を直に読んでも中身と対象を読めない。同じ配信元でスクリプトを実行できる人には、この保護は効かない
- 送る直前に、送る token とセッションと持ち主を照合し、照合から送信の開始まで待ちを挟まない。サインアウトとアカウントの切り替えが間に入らないようにするためである
- 保留の一覧は、対象を今の権限で見られると確かめられたときだけ、入力やサーバー由来の値を出す
- 暗号の IV を作る `crypto.getRandomValues` は `crypto.ts` の 1 か所だけで呼ぶ（横断の部品を通さない理由を注釈に書いてある）

## 運用

- この層を本番の起動につなぐのは [#196](https://github.com/devbasex/nd-factory/issues/196) である。つなぐまで、利用者のブラウザーに `nd-device` と `nd-quarantine` は作られない
- 版を上げるときは、`db.ts` の版と `migrate.ts` の移し方を同じ変更で足す
- 端末のキャッシュの量の上限と、実機での鍵の置き場と強さは、まだ確かめていない
- 次の 2 つは、まだ実装に無い。本番の起動につなぐ前に足す
  - 見られる対象の記録を復号できないときに、記録と写しを消して段 1 から読み直す扱い（今は回が失敗して終わる）
  - 取り下げが 409 `already_delivered` を受けたときに、会話の写しを読み直して、項目が渡ったか先に取り下げられたかで表示を分ける扱い（[オーガナイザーの渡し方と取り下げ](../design/organizer.md#渡し方と取り下げ)。今はほかの恒久の拒否と同じに扱う）
