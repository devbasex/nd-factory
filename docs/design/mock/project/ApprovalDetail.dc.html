目的

  • 今: 2 つの版の下限が環境の設定に無く、Lambda に届かない
  • 誰に: dev を立てる運用者と、予算を既定へ戻したい利用者
  • 変えると: 設定に書いた下限が実行の依存の 4 つの Lambda に届く

適用範囲・あるべき姿の根拠

  • 環境の設定・API のスタック・テスト。サービスのコードは変えない
  • 根拠 5 件（実測 3・要求の前提 1・SemVer 2.0.0）

決めたこと

設計文書の見出しのまま
番号決定理由・退けた案
1空の値を template に残さないため、空の下限は環境変数を名前ごと足さない理由 空の文字列を渡すと、サービスは「下限なし」と「設定の誤り」を区別できない退けた案 空の文字列を渡し、サービスで空を無視する（サービスのコードを変えることになる）
2サービスが読めない値で反映しないよう、版の形の検査を標準ライブラリの正規表現で書き、サービスの読み方の部分集合にする理由と退けた案を開く
3予算の知らせの項目と取り違えないよう、2 つの項目の名前を環境変数の名前の小文字にする理由と退けた案を開く
