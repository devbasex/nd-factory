# 作り直しの全体設計: 子の切り方と、子ごとの詳細設計で書くこと

頭の文書は [05-overall.md](05-overall.md) にある。この文書は、骨組みと検査と土台と試走の子（骨組み・#1〜#3）と、機能の子（M1〜M10、#4〜#13）の切り方を扱う。

## 子の切り方

### 切り方の決まり

| 決まり | 中身 |
| --- | --- |
| 1 子 1 PR | revert 1 回で戻せる大きさにする。PR の行数の上限は検査（#1）が持つ |
| 子の本文 | 機能の対応表（[対応表の設計](03-parity.md)）の行の ID の一覧と、触るパスを持つ |
| 閉じる条件 | 自分の行が試走（#3）で `passed` で、`dev_state` が `未調査` でなく `verify_new` が `未決` でない。単体のテストが通るだけでは閉じない。#3 の閉じる条件の検査は、行き先の子の行に `未調査`・`未決` が残れば閉じる前に止める（[対応表の設計](03-parity.md)の決定 13、[判定の規則](01-rules.md)の I5・R9）。#3 自身は、行き先の子を持たない作らない行（`to` の無い行）に `未調査`・`未決` が残れば閉じない |
| 並列 | 機能の子は同時に 3 本まで（作り直しの計画（旧い側の作り直しの親の課題）） |
| 追補 | 閉じた子への追加の作業は、元の子の番号を引く新しい課題にする。追補が 10 を超えたら、この全体の設計を直す |
| 影響評価 | 子の設計は [影響評価の欄](06-overall-architecture.md#影響評価の欄)を持つ |

### 骨組み・検査・土台・試走

| 子 | 受け持つ範囲 | 前に要る子 | 縛る不変条件 |
| --- | --- | --- | --- |
| 骨組み | 新しいリポジトリの初期の構成（パッケージ・CDK・CI・宣言）、端から端まで通る最小の縦の切れ端（ログイン → API の 1 経路 → 表 → 画面 1 枚）を運用する環境へ反映、設置のコマンド、反映のパイプライン、設計文書の移し方 | 全体の設計の承認 | I12（最初の 1 経路で配列の受け渡しを固める） |
| #1（検査） | 漏れの検査・境界の検査・呼び出し側と表の照合・形の往復・閉じる語・PR の大きさ・横断の部品の外での直の利用・版の数字と内部のスクリプトの検査・契約の照合のジョブ | 骨組み | I8 |
| #2（土台） | 形の正本（`packages/contracts/`）・横断の部品（`packages/core/`）・サービスの表の定義・AWS と GitHub と Cognito のアダプター | 骨組み | I9・I12 |
| #3（試走） | 機能の対応表の全行を運用する環境で毎スプリント流し、行ごとの結果と通った行の数を記録する。行き先の子を持たない作らない行（[対応表の設計](03-parity.md)の決定 13 の 12 行と、後から足した `to` の無い行）の `dev_state`・`verify_new` を、自分の設計承認ゲートで C3 と同じく埋める | [対応表の設計](03-parity.md)・骨組み | — |

画面の順序はプロジェクト MVV の Value 2（画面先行）に従う。M9 が画面の土台と各機能の画面をダミーデータで作り切ってから、機能の子（M1〜M8）が API の中身を作り、自分の PR で画面のダミーデータを API へつなぎ替える。そのため M1 は M9 を前に要し、M2 以降は M1 を通して M9 の後になる。

### 子ごとの詳細設計で書くこと

どの子も、詳細設計で次の 8 項目（作り直しの調査（ndf-next の反省。旧い側。移していない）の 4 節の C）を書く。

| # | 項目 |
| --- | --- |
| C1 | 触るパスでのファイル配置と、関数の粒度の仕様 |
| C2 | 新しく作る関数どうしで共有する部品、複数の関数に出る語、ファイルの大きさの見積り、テストの置き場 |
| C3 | 機能の対応表のどの行を通すか（行の ID）と、試走の手順。自分の行の `dev_state`（`未調査` を実機で確かめた値へ）と `verify_new`（`未決` を新しいリポジトリでの入力と成功の条件へ）を埋め、対応表の検査を通した PR で入れる（[対応表の設計](03-parity.md)の決定 13） |
| C4 | 呼び出し側（画面・CI・文書・hook）の一覧と、照合の検査 |
| C5 | 設定のキーごとに読む所があること |
| C6 | スキーマの例と既存の値を読み手に通すテスト |
| C7 | 旧い側の該当する不具合の直しと、その回帰テスト |
| C8 | 詳細設計を単独でレビューすること。実装の後に、再利用の決定が守られたかを照らすこと |

子ごとに、8 項目に加えて特に書くことを次に並べる。

| 子 | 8 項目に加えて書くこと |
| --- | --- |
| 骨組み | 設定のファイルの置き場（運用する環境の分）・設置のコマンドの入出力と終了コード・反映のパイプラインの承認の資料・設計文書を新しいリポジトリへ移す手順 |
| #1 | 検査ごとの対象のパス・許可の一覧の置き場・止める自動の書き手の一覧 |
| #2 | サービスの表の列と索引・形の版の 2 段の出し方・横断の部品の公開の関数・アダプターの失敗の分類 |
| #3 | 試走の結果の記録の形・行の合否の判定の手段・毎スプリントの流し方 |
| M1 | 使える量の表のデータの形と、上限なしの行の選び方 |
| M2 | 割り当ての履歴の行・構成リポジトリの登録の順序（主が先） |
| M3 | 区間の結果の行の読み方・承認の守り（防ぐと照らす）と、その未確認の点を固定の版の NDF で確かめた記録・引き換えの手順・DB の用意のタスクの冪等・承認の待ちで止めたタスクの後に NDF のループを続けられることを確かめた記録 |

| M7 | AI のオーガナイザーのレーンの割り当てを実行の制御へ依頼する口 |

| M10 | 実測の手順と記録（一時停止・再開・keepalive・ECS.2）・予算の知らせの宛先の受け方 |
