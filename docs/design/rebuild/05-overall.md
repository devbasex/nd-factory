# 作り直しの全体設計: 骨組みと機能の子が、モデル・境界・入出力・状態の置き場・権限を決め直さずに詳細設計へ進める

## 目的

- **今どうなっているか**: 作り直しの子（骨組みと #1〜#13）は、全体の構造（モデル・境界・入出力の規約・状態の置き場・権限）を持たないまま並んでいる。NDF の作り直し（devbasex/ai-plugins#1142）は同じ状態で実装に入り、決定の 38% を実装の後に足した
- **誰に効くか**: 骨組み・検査（#1）・土台（#2）・試走（#3）と機能の子（M1〜M10）の担当者、設計承認ゲートで読む人、nd-factory を自分の AWS アカウントへ設置する人
- **変えると何が成り立つか**: 子の担当者がこの設計だけを読んで、モデル・境界・入出力の規約・状態の置き場・権限を新たに決めずに詳細設計へ進める。NDF 11 の契約と将来構想（状態の正本をサーバー側の DB に置く・レーンをコンテナへ割り当てる・公開された言語だけでやり取りする）に、最初から合う

## 適用範囲

- **働く範囲**: 作り直しで devbasex に作る新しいリポジトリ（名前は作り直しの未決で決める）のサービスのコードとインフラの定義。旧い側（旧いリポジトリ）のコードと API には触れない
- **プロジェクトごとに違うもの**: 設置する AWS アカウントとリージョンは AWS の profile から受け、それ以外の環境の値は設定のファイル（リポジトリの外に置く）から受ける（[状態とインフラ](08-overall-state-infra.md#環境の値の受け方)）
- **当たるモード**: `standard`

#### オーガナイザーの 2 つの集約

旧い側の「Factory のオーガナイザー」は、サーバーのコード（決まった芯）と AI のセッション（AI のオーガナイザー）の 2 つを同じ語で呼んでいる。作り直しでは次のとおり分ける。

| 今の呼び方 | 作り直しでの置き場 | 理由 |
| --- | --- | --- |
| 決まった芯（リリースを 1 本にまとめる・待ちの判定・止まったリリースを解く） | 実行のコンテキストの集約「リリースのまとめ」。持ち主は実行の制御 | レーンとスプリントの実行の状態だけで決まり、会話を持たない |
| AI のオーガナイザー | オーガナイザーのコンテキストの集約。動く場所はレーンの 1 つ（オーガナイザーのレーン）で、レーンの割り当ては実行の制御へ依頼する | 会話と人への問いを持ち、プロジェクトに 1 つだけ動く |

「Factory のオーガナイザー」の語は新しいリポジトリでは使わない。改名の保留が解けたときは、この 2 つの集約の名前だけを差し替える。

#### プロジェクトの器

プロジェクトは主リポジトリ 1 つとサブリポジトリ 0 以上の集まりで、どのアカウントに属するかは割り当て（次の段落）だけで決まる。1 レーンは 1 リポジトリだけを扱い、リポジトリをまたぐ作業は NDF の計画の宣言（レーンの `repo` と `after`）で表す。宣言の形（devbasex/ai-plugins#2653）が決まるまでは、器と構成リポジトリの一覧だけを持つ（[決定の記録](11-overall-decisions.md)の決定 4）。

#### チームへの割り当て

チームはチームのアカウント（個人のアカウントは 1 人のチームとして扱う）である。プロジェクトを見られるのは、割り当てたチームの席を持つ人と、その人が委任したエージェントだけである。割り当てを作る・変える・外すのは人だけが確定できる操作である（P3）。割り当てとアカウントの関係は次のとおりに決める。

| 問い | 決まり |
| --- | --- |
| 1 つのプロジェクトを割り当てるチームの数 | 同時にちょうど 1 つ（I15）。実体関連図の 0 以上は、変更ごとに足す履歴の行を数えたもので、今の割り当ての行は 1 つだけである |
| 持ち主のアカウント | 持ち主は、今割り当てているチームのアカウントそのものである。割り当てと別に持ち主を持たないため、持ち主と割り当てたチームが食い違う状態を作れない |
| 作ったとき | プロジェクトを作った人が操作したアカウント（個人のアカウントなら 1 人のチーム）へ、作成と同じ操作で割り当てる（E3）。割り当ての無いプロジェクトを作る経路を持たない |
| 割り当てを変える | 別のチームへ移す操作で、今のチームの持ち主（席の役割が持ち主の人）が画面で確定し、移す先のチームの持ち主が画面で受け入れたときに成り立つ。どちらも人だけが確定できる（I3）。レーンを止めるのは移す操作で、人が先にスプリントを取り消しておく前提は置かない。今のチームの持ち主の確定が、そのプロジェクトの終わっていないレーン（承認の待ちでタスクを止めたレーン（決定 25）を含む）をスプリントの取り消しと同じ経路で止め、そのレーンの token を断ち、手元のマシンへの割り当てを外し、続けてそのプロジェクトの進行表の DB の役割のパスワードを差し替えて今の接続を切る（推論の一時の資格情報の取り直しも断ち、ランナーへ渡し済みの GitHub の token を失効させる。[資格情報の失効](09-overall-trust.md#ecs-のタスクの種類と権限)）。確定から受け入れまでの間は、そのプロジェクトでレーンを始める要求を 409 で拒む。受け入れはレーンを止めず、停止が終わったことだけを照らす。割り当ての行の差し替えと、終わっていないレーンの有無と DB の役割のパスワードの差し替えが終わったことを同じ条件つきの書き込みで照らし、レーンが 1 つでも残るか差し替えが終わっていない間は受け入れを 409 で拒む（I15）。今のチームの持ち主は、受け入れの前なら確定を取り下げられ、取り下げた後は、DB の役割のパスワードの差し替えが終わってから（失敗ならやり直しが終わってから）そのプロジェクトでレーンを始められる。差し替えが終わるまでは取り下げた後もレーンの開始を 409 で拒む（[差し替えが失敗したとき](09-overall-trust.md#ecs-のタスクの種類と権限)）。確定で止めたレーンは取り下げても戻らず、スプリントを始め直す。受け入れの期限を置くかとその長さは、M2（#5）の詳細設計で決める。移した後のレーンは、移す先のチームの実行の手段（ホステッドか、移す先のチームが登録した手元のマシン）にだけ割り当てる |
| 割り当てを外す | プロジェクトを閉じる操作としてだけ持ち、今のチームの持ち主が確定する。外した後はどのチームからも見えず、レーンを始められない。中身の保存期間は M2 の詳細設計が決める |
| 見える範囲を広げる（割り当てたチームの外へ見せる） | 作り直しでは作らない。1 チームの割り当てだけで I2 を満たす |
| 使える量と進行表の DB | 今割り当てているチームのアカウントの使える量で数える。進行表の DB はプロジェクトごとに分けるため（I10）、移しても DB は移さない |
| F3 の「チームの持ち主」 | 今割り当てているチームの持ち主。移すときは移す先のチームの持ち主も受け入れの確定を行う |

### 不変条件

| # | 集約 | 条件 | 破れたときの扱い |
| --- | --- | --- | --- |
| I1 | プロジェクト | 構成リポジトリのうち主リポジトリはちょうど 1 つ | 主の無い登録・2 つ目の主の登録を 409 で拒む |
| I2 | プロジェクトの割り当て | プロジェクトとその中身（リポジトリ・課題・スプリント・承認資料・記録・知らせ）は、割り当てたチームの席を持つ人と、その人の委任だけが読める。ランナー（レーンの token）・手元のマシン（登録の token）・DB の用意のタスク（引き換えの token）は例外で、自分に割り当てたレーンかタスクのプロジェクトの分だけを、自分向けの経路（[主体と資格情報](09-overall-trust.md)の表）で読める。ほかの主体には存在しないときと同じ応答を返す | 認可の判定が 404 を返す。一覧と件数からも除く |
| I3 | プロジェクトの割り当て | 割り当ての作成・変更・削除は、人が画面で確定した要求だけが通る | 委任の資格情報・レーンの token からの要求は 403 で拒む |
| I4 | 承認の依頼 | 答えを確定できるのは人だけで、つながっていない端末では確定しない。確定の時点でサーバーの今の状態（待っている・承認資料の要約値が同じ）と照らす | 照らして合わなければ 409 を返し、確定しない |
| I5 | 承認の依頼 | 1 つの承認の依頼の答えは NDF へ 1 回だけ渡る（冪等の鍵が答えの ID） | 同じ鍵の 2 回目を NDF が受けても状態を変えない。違う鍵が 2 つ渡ったら、レーンを止めて人へ知らせる |
| I6 | スプリントの実行 | 区間の結果の行が無いか、契約に無い値なら、その区間は失敗 | 失敗した区間を含むセグメントを失敗で閉じ、理由を進捗の事象に残す |
| I7 | スプリントの実行 | 1 つのレーンの今のタスク（コンテナ）は同時に 1 つだけ。決定 25 の起こし直しでは、レーンの割り当てを外さずに、前のタスクの終わりを確かめてから、条件つきの書き込みで今のタスクを新しいタスクへ差し替える | 前のタスクが終わっていない間の 2 つ目の割り当てと差し替えを、条件つきの書き込みで拒む |
| I8 | アカウント | 使える量の判定は 1 か所だけで行い、画面は料金プランの名前で分岐しない | 判定の外で上限を比べるコードを検査が落とす |
| I9 | 操作の記録 | 記録は追記だけで、秘密と個人情報の値を含まない。読み取りを含むすべての操作が 1 件ずつ残る | 書けなければ操作を 503 で失敗させる |
| I10 | スプリントの実行 | 進行表の DB は、プロジェクトごとに別のデータベースとログインの役割を持つ（名前空間が無い間の仮置き）。見せる範囲の単位（I2）と同じ単位で分ける | 他のプロジェクトのデータベースの URL を渡す経路を作らない。テストで縛る |
| I11 | スプリントの実行 | ECS のタスクの役割は、どのタスクの種類（[ECS のタスクの種類と権限](09-overall-trust.md#ecs-のタスクの種類と権限)の表）でも AWS の権限を持たず、レーンの token はレーンが動く間だけ有効。`managed` のレーンの推論は、API が推論の役割を引き受けて渡す 1 時間の一時の資格情報だけで呼び、`byok` のレーンと DB の用意のタスクには渡さない。ECR からの取得とログの書き込みは、ECS のエージェントが使うタスクの実行の役割が受け持ち、タスクの中のプログラムからは使えない | レーンの終わり・取り消しで token を断ち、推論の一時の資格情報の取り直しを断る |
| I12 | （全集約の API） | API の入出力は取得・作成・更新・削除とも配列で受け渡す | 配列でない本文を 400 で拒む |
| I13 | 進捗の事象 | 書くのは進捗の受け口だけで、追記だけ。同じレーンの同じ連番は 1 件だけ | 更新と削除の経路を持たない。同じ連番の 2 件目は前の 1 件を返し、足さない |
| I14 | 起票の依頼 | 1 件の依頼に結果はちょうど 1 件で、起票しないときは理由を持つ | 結果の無い依頼を見回りが拾って知らせる。理由の無い「起票しない」を 400 で拒む |
| I15 | プロジェクトの割り当て | 1 つのプロジェクトの今の割り当ては 1 つのチームだけ。プロジェクトの持ち主は今の割り当てのチームのアカウント。終わっていないレーンが残るプロジェクトは移せない。今のチームの確定が終わっていないレーンを止め、受け入れの前なら確定を取り下げられる | 2 つ目の今の割り当てを条件つきの書き込みで拒む。今のチームの確定で、終わっていないレーン（承認の待ちで止めたレーンを含む）を取り消しと同じ経路で止めて token を断ち、進行表の DB の役割のパスワードを差し替えて今の接続を切り、ランナーへ渡し済みの GitHub の token を失効させる（進行表の DB がまだ無いプロジェクトでは差し替えを要らないと記録し、作成中なら確定を 409 で拒む）。移す先の受け入れは、割り当ての行の差し替えとレーンの有無と DB のパスワードの差し替えの終わりと期限の前の GitHub の token が残っていないことを同じ条件つきの書き込みで照らし、終わっていないレーンが残るか差し替えが終わっていないか token が残っていれば 409 で拒む。確定から受け入れまたは取り下げまでの間と、取り下げた後も DB のパスワードの差し替えが終わるまでのレーンの開始とその間の確定し直しを 409 で拒む。差し替えは保留の版の値で行い、終わりを受けてから今の版にする。DB のパスワードの変更と接続の切断は、管理の接続先の記録の表の差し替えの番号を行の lock で照らし、記録より大きい ID のタスクだけが行う |

### 用語

| 用語 | 意味 | 用語集への反映 |
| --- | --- | --- |
| プロジェクトの割り当て | プロジェクトを見られるチームを決める関係。チームはチームのアカウントで、個人のアカウントは 1 人のチームとして扱う。作る・変える・外すのは人だけ | 追加 |
| リリースのまとめ | 同じプロジェクトで並行するレーンのリリースを 1 本にまとめ、待ちを判定し、止まったリリースを解く集約。旧い側の決まった芯の役割を引き継ぐ | 追加 |
| Factory のオーガナイザー | 旧い側で、決まった芯と AI のオーガナイザーの 2 つを指す語。新しいリポジトリでは使わず、リリースのまとめと AI のオーガナイザーに分ける | 意味を変える（新しいリポジトリで使わないことを足す） |
| 決まった芯 | 旧い側の Factory のオーガナイザーのうち、API の handler と見回りの中で動くコード。新しいリポジトリではリリースのまとめと呼ぶ | 意味を変える（新しいリポジトリではリリースのまとめと呼ぶことを足す） |
| AI のオーガナイザー | プロジェクトに 1 つ動く AI のセッション。リリースはまとめず、リリースのまとめへ依頼する。動くレーン（オーガナイザーのレーン）の割り当ては実行の制御へ依頼する | 意味を変える（依頼先を決まった芯からリリースのまとめへ、レーンの割り当てを実行の制御への依頼へ） |
| レーン | サービスがコンテナへ割り当てる流れの単位。開発ループ 1 つか、手動のスプリントの実行 1 つか、リリースの実行 1 つ。今のタスク（コンテナ）は同時に 1 つだけで（I7）、ホステッドのレーンは承認の待ちでタスクを止め、割り当てを外さずに同じレーンへ新しいタスクを起こし直す（決定 25） | 意味を変える（「1 度だけ割り当てる」を「今のタスクは同時に 1 つ。起こし直しで差し替える」へ） |
| セグメント | スプリントの実行の中で、ランナーのプログラムが 1 つの始まり（課題・周回の始まり・答え・リセットの後・リリースの手）から次の止まり（承認の依頼・終わり・利用上限）まで NDF の conductor を動かした 1 回。1 つのセグメントは 1 つ以上の区間からなる。ホステッドのレーンでは、承認の依頼で止まったセグメントの後にタスクを止め、答えから始まる次のセグメントで同じレーンに新しいタスクを起こし直す（決定 25） | 意味を変える（区間との関係と、ホステッドのレーンでの起こし直しを足す） |
| 区間 | 1 つのセグメントの中でランナーが起動する claude -p の 1 回分。conductor の ndf-next で次の区間へ移る。区間の終わりに最後の結果の行を 1 つ読み、無いか契約に無い値なら区間は失敗で、それを含むセグメントも失敗で閉じる（I6） | 意味を変える（結果の行の読み方と失敗の扱いを足す） |
| プロジェクト | 主リポジトリ 1 つとサブリポジトリの集まり。課題・承認・リリースの順を共有する。GitHub での持ち主（組織）と公開範囲が違うリポジトリも 1 つにでき、宣言は構成リポジトリのうち最も閉じたものに置く。プロジェクトそのものの持ち主は、今割り当てているチームのアカウントである（I15） | 意味を変える（プロジェクトの持ち主を足し、リポジトリの持ち主と分ける） |
| 進行表の DB | NDF の進行表と DBOS の耐久の記録を置く PostgreSQL。サービスは URL を `NDF_PROGRESS_DB` で ECS のタスクへ渡すだけで、中身を読み書きしない | 追加 |
| 形の正本 | API の経路と形・型・JSON Schema・環境変数・CDK のパラメーター・終了コードを 1 つずつ定義し、ほかの表現を生成する元 | 追加 |
| 契約の照合のジョブ | NDF の契約の見本（`entrypoint-cases.json`）に、nd-factory の翻訳と呼び出しを定期に照らす CI のジョブ | 追加 |
| 引き換えの token | ECS のタスクを起こすときに渡す 1 回だけ使える短い token。タスクは起動の直後に API でレーンの token と引き換える | 追加 |
| 上限なしの行 | 使える量の表の行のうち、自分で設置した環境が使う行。上限の判定と課金を切る | 追加 |

要求の「用語」の 4 語（作り直し・自分で設置する人・運用する環境・仮置き）は、要求の工程で用語集へ追加済みで、意味を変えない。

| 1 か月の費用 | 見込みは月 1〜6 ドル（作り直しの親の課題（旧い側）。計算の費用はタスクの動く時間に比例）。承認の待ちの間はタスクと DB の接続を持たないため、この前提が成り立つ（[費用の予算と資源の枠](08-overall-state-infra.md#費用の予算と資源の枠)）。骨組みを反映した後の 1 か月の請求で確かめ、やめる判断の 1 回目の材料にする |
