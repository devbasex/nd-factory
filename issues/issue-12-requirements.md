## 何が起きたか

nd-factory の全体の設計（[#24 全体の設計と開発計画](https://github.com/devbasex/nd-factory/issues/24)）は、画面を機能の API より先に作る順（Value 2 画面先行）を決め、画面の共通の仕組み（画面の基盤）をこの課題に切り出した。今の画面（`apps/web/`）は骨組みのままで、サインインした利用者の ID を出す 1 枚の画面しか無い。2026-11-24 には、最初の画面を AI のオーガナイザーの一覧と会話にする利用者の決定（[#140 画面の地図をオーガナイザーの会話を主にした形へ戻す](https://github.com/devbasex/nd-factory/issues/140)）があり、画面マップは 16 本の HTTP のルートになった。画面のモック（`docs/design/mock/`）は、オーガナイザーの画面だけが新しい地図で、ほかは作り直す前の画面のままである。

## 種類

機能追加（骨組みの画面（`apps/web/`）は既にあり、そこへ画面マップ・共通の部品・オフライン・国際化を足す）

## 今の姿

- 画面（`apps/web/src/`）は、HTTP のルートを持たない 1 枚の画面で利用者の ID を出す。文言は `view.ts` に日本語で直に書き、ログインのキャッシュはタブの `sessionStorage` に置く。Web App Manifest と Service Worker は無い。設計との違いの 7 行は [開発の経緯の「画面の合わない所」](https://github.com/devbasex/nd-factory/blob/main/docs/design-process/issue-24/history.md#画面の合わない所) にある
- 画面の設計は [画面の文書](https://github.com/devbasex/nd-factory/blob/main/docs/design/screens.md) が決めている（手数の目標・画面マップ・共通の部品とデザインの規約・端末の幅・オフライン・国際化・ダミーデータで作り切る段。決定 20〜39・120）
- 画面のモックの正本は [`docs/design/mock/`](https://github.com/devbasex/nd-factory/blob/main/docs/design/mock/README.md) で、公開先はキャンバス https://claude.ai/artifact/Vo1wCNvE9cYfPTtVWSoAdR である。ページ「オーガナイザー（#140）」だけが新しい地図で、ページ「旧い側の画面（作り直す前）」は旧いナビゲーションのままである

## 何を足すか・変えるか

| | 今 | 足した後 |
| --- | --- | --- |
| 画面のモック | オーガナイザーの画面だけが新しい地図 | 16 本の HTTP のルートと会話を主にした地図で作り直し、利用者が承認し、キャンバスへ公開し直す |
| HTTP のルート | 持たない（1 枚の画面） | 画面マップの 16 本（R1〜R16）を URL の path で持ち、最初の画面は R2 オーガナイザー（一覧と最後に開いた会話）。画面マップに無いルートは `/` へ置き換える |
| ナビゲーション | 無い | 4 つの行き先（オーガナイザー・承認待ち・スプリント・設定）と、チームとプロジェクトの切り替え |
| 共通の部品 | 無い | 部品の一覧・状態のバッジ・デザインの規約（押せる要素 44 px 以上） |
| 端末の幅 | 考えていない | 区切りの幅 640 px と 1024 px で、スマートフォン・タブレット・PC の配置に分ける |
| オフライン | 無い | PWA（Web App Manifest）・Service Worker（画面の殻と設定の値だけを保存）・暗号化した IndexedDB の端末のキャッシュ（受け取ってから 14 日）・サインアウトで消す・操作の 3 つの区分（キャッシュして送る・確定待ち・つながってから押す）・つながったときのそろえ方 |
| ログインのキャッシュ（refresh token） | タブの `sessionStorage` に置き、タブを閉じると消える | 暗号化した IndexedDB に置き、タブを閉じても残す。`sessionStorage` のログインのキャッシュは、移す PR で消す |
| 文言・日時・数・金額 | `view.ts` に日本語で直に書く | 翻訳のファイルのキーで引き、日時・数・金額を利用者の言語と時刻帯で出す |
| ダミーデータ | 無い | ダミーのクライアントを起動の組み立ての 1 か所で差し替え、検索の値 `scenario`・`connection` で状態を切り替える |
| 骨組みの利用者の表示 | 1 枚の画面 | 画面の基盤の上へ置き直す（#4 と分けて持つ） |

## 今の利用者への影響と互換

骨組みの画面は利用者の ID を出すだけで、運用で使う画面はまだ無い。最初の画面が利用者の表示からオーガナイザーに変わる。ログインのキャッシュを置く場所が変わるため、移す版を反映した後にサインインし直しが要るかは「未決」に置く。

## なぜ困るか

画面の基盤が無いと、機能の画面（[#28 機能の画面をダミーデータで通しで操作できる](https://github.com/devbasex/nd-factory/issues/28)）が部品・幅・オフラインの見せ方を画面ごとに決め、見た目と振る舞いがそろわない。手数の目標を数える仕組みが無いと、手数を増やす変更に気づけない。移動中やつながらない場所では、最後に受け取った承認資料も読めない。

## 目的

| MVV の項目 | この課題で受けること |
| --- | --- |
| Value 2 画面先行 | 画面の地図・部品・端末・オフラインの見せ方・国際化を、機能の画面より先に画面の基盤として固める |
| Value 3 どこでも、つながらなくても | スマートフォンとタブレットで操作でき、最後に受け取った中身を暗号化した端末のキャッシュから読め、取り消せない確定はつながってから行う |
| Value 5 国や地域を越えて | 翻訳のファイルで文言を持ち、日時・数・金額を利用者の言語と時刻帯で出す |
| Value 1 操作を速く分かりやすく | 場面ごとの手数の目標を e2e で数え、超えたら落とす |

機能一覧の行は持たない（F1〜F20・F24・F25 の画面の基盤）。受け持つ不変条件は I4（確定待ち）である。

| # | 中身 |
| --- | --- |
| I4（確定待ち） | 設計やリリースの承認と、秘密の扱いや元に戻せない変更など人の承認が必要な操作への回答は、つながっていない端末では確定しない。接続が戻ってから、サーバーが依頼の状態（まだ待っているか）と読んだ承認資料（押したときから変わっていないか）を確認してから確定する。押したときに画面が答えの ID を作り、同じ回答を 2 回送っても 1 回として扱われるようにする。どの操作が当たるかの正本は、[全体の設計の不変条件 I4](https://github.com/devbasex/nd-factory/blob/main/docs/design/overview.md#不変条件) と [画面の文書の操作の 3 つの区分](https://github.com/devbasex/nd-factory/blob/main/docs/design/screens.md#操作の-3-つの区分) の「確定待ち」の行である |

## 対象範囲

含む:

- 最初の工程: 画面のモック（`docs/design/mock/`）を新しい地図（16 本の HTTP のルート・会話が主）に作り直し、利用者がモックを承認する。キャンバス https://claude.ai/artifact/Vo1wCNvE9cYfPTtVWSoAdR へ公開し直す
- 画面マップ: 16 本の HTTP のルート（R1〜R16。最初の画面は R2 オーガナイザーの一覧と会話）・遷移・ナビゲーション（オーガナイザー・承認待ち・スプリント・設定）・チームとプロジェクトの切り替え
- 共通の部品・状態のバッジ・デザインの規約（押せる要素 44 px 以上）
- 端末の幅（区切りは 640 px と 1024 px）
- オフライン: PWA・Service Worker（画面の殻と設定の値だけ）・暗号化した IndexedDB の端末のキャッシュ（14 日）・サインアウトで消す・操作の 3 つの区分（キャッシュして送る・確定待ち・つながってから押す）・つながったときのそろえ方
- ログインのキャッシュ（refresh token）を暗号化した IndexedDB に置く。骨組みの `sessionStorage` のログインのキャッシュは、移す PR で消す
- 国際化: 翻訳のファイル・日時・数・金額
- ダミーのクライアントの差し替えの口（起動の組み立ての 1 か所）と `scenario`・`connection` の切り替え
- 骨組みの画面の 1 枚の利用者の表示を、画面の基盤の上へ置き直す（#4 と分けて持つ）

含まない:

- 機能の画面（[#28 機能の画面](https://github.com/devbasex/nd-factory/issues/28)）
- Web Push の送り手と通知先の API（[#8 人の判断と知らせ](https://github.com/devbasex/nd-factory/issues/8)）。委任からの確定を縛るテストも #8 が持つ
- API の中身
- サインインの戻り先と連携の `state` をタブの `sessionStorage` に置く扱い（画面の文書の決まりのまま残す。消すのはログインのキャッシュだけ）

## 前提

- 前提 1: スキーマの正本と横断の部品（[#2 1 つの操作の表から型・API・MCP の道具・ダミーデータを作れる](https://github.com/devbasex/nd-factory/issues/2)）から、操作の表で作った API のクライアントの型とダミーデータを受ける。#2 が終わる前に、それを読む部分の実装を始めない
- 前提 2: 1 つの子は 1 つのスプリント（NDF の 1 版）で閉じる大きさにする。超えると分かったら、詳細設計で子を分けて本文を直す
- 前提 3: 全体の設計（画面の文書の決定 20〜39・120 と、全体の設計の I4）は決め直さない。決め直す必要が出たら、全体の設計を直す PR を先に出す
- 前提 4: 受け入れ条件 1〜9 は起票の時点の条件である。10〜17 は、対象範囲の項目に判定の条件が無かったため、要求と受け入れ条件の工程が画面の文書の決定から足した。設計承認ゲートで承認する人が確かめる
- 前提 5: 実機で確かめる項目（受け入れ条件 8）は、ダミーで測れるものは設計と実装の段で測る。API をつないだ後に測り直す項目は、ダミーを使った計測の後、実 API を接続した検証用の配信環境（画面を CDN から配信し、設置した本物の API を呼ぶ環境。手元の `vite preview` ではない）で同じ操作を測り直す

## 受け入れ条件

- [ ] 1. 新しい地図のモックを利用者が承認している
- [ ] 2. I4（確定待ち）: オフラインの端末からの確定と、待ちが解けた後・承認資料が変わった後の確定のテストがある。確定が通ると落ちる（委任からの確定は #8 が縛る）
- [ ] 3. 手数の目標を e2e で数え、手数とページの数が上限を超えたら落とす。待ち時間の測り方を e2e の回線の絞りで決める
- [ ] 4. 部品の一覧と置き場の一致をテストで照らす
- [ ] 5. 画面の操作とスキーマの正本の操作の一覧の対応を検査で照らす
- [ ] 6. 端末のキャッシュからの表示の性能を測り、結果を残す
- [ ] 7. 骨組みの `sessionStorage` のログインのキャッシュが無い
- [ ] 8. 確かめる項目を実機で確かめ、結果を詳細設計に残す: iOS の Safari での Web Push・端末のデータの暗号化の鍵の置き場と強さ・主なブラウザでの Badging と Background Sync・手数の目標の待ち時間（ダミーで回線を絞って測り、実 API を接続した検証用の配信環境で同じ操作を測り直す）・30 日に近いログインのキャッシュから通知を開く・ホーム画面に加えた場合と加えない場合の Safari のキャッシュ・Cognito の access token を 15 分にしたときの取り直し・Web Push の本文の暗号化の方式（RFC 8291）の細部
- [ ] 9. 詳細設計 `issues/issue-12-design-detail.md` を書き、全体の設計で決めたモデル・境界・入出力・状態の置き場・権限を決め直していない
- [ ] 10. 画面マップの 16 本の HTTP のルートを URL の path で直に開くと、その画面が出る。画面マップに無い path を開くと、履歴を置き換えて `/` へ移る（e2e）
- [ ] 11. 幅 640 px 未満・640 px 以上 1024 px 未満・1024 px 以上のそれぞれで、ナビゲーションの 4 つの行き先が同じ順で出る（スマートフォンは下の帯・タブレットは細い帯・PC は横の帯。e2e）
- [ ] 12. 3 つの幅のどれかで、押せる要素の幅か高さが 44 px 未満だと e2e が落ちる
- [ ] 13. 端末のキャッシュに置いた API のレスポンスは、IndexedDB の中身を直に読んでも平文で読めず、Service Worker の保存先には API のレスポンスが無い（テスト）
- [ ] 14. 受け取ってから 14 日を過ぎた端末のキャッシュは画面に出ない。サインアウトすると、端末のキャッシュとログインのキャッシュが端末から消える（テスト）
- [ ] 15. つながっていない端末では、「つながってから押す」の操作が押せず「つながると使えます」が出る。「キャッシュして送る」の操作は押せ、つながった後に溜めた順に送られる（テスト）
- [ ] 16. 言語を切り替えると、画面の文言が翻訳のファイルの文に変わる。日時は利用者の時刻帯で出る（テスト）
- [ ] 17. 本番のビルドの成果物にダミーのクライアントとダミーのフラグが無いことを、ビルドの検査が確かめる。ダミーの mode では `scenario` と `connection` の値で画面の状態が変わる（検査と e2e）

## 非機能の条件

| 大項目 | 条件 |
| --- | --- |
| 可用性 | つながっていない端末でも、最後に受け取ったスプリントと承認資料を端末のキャッシュから読める |
| 性能・拡張性 | 画面の文書の手数の目標の待ち時間（例: S2 は端末のキャッシュから 1 秒以内に描く）を、4G 相当に回線を絞った e2e で測る |
| セキュリティ | 端末のキャッシュとログインのキャッシュは、取り出せない AES-GCM のキーで 1 件ごとに暗号化する（画面の文書の決定 30）。サインアウトで消す。例とサンプルには作り物の値だけを使う |
| システム環境 | スマートフォン・タブレット・PC の主なブラウザ（iOS の Safari を含む）。対応の細部は受け入れ条件 8 で実機で確かめる |

## 影響

| 対象 | 影響 |
| --- | --- |
| 公開インタフェース | 変わらない（API・設定のファイル・設置のコマンドの形は変えない。画面の URL と最初の画面の変化は「既存の振る舞い」の行に書く） |
| データ | サーバーのデータは変わらない。端末に IndexedDB の端末のキャッシュとログインのキャッシュを新しく置く |
| 既存の振る舞い | 画面の URL が画面マップの 16 本になり、最初の画面が骨組みの利用者の表示からオーガナイザーに変わる。骨組みの利用者の表示は画面の基盤の上へ移る。ログインのキャッシュはタブを閉じても残るようになる |

## 用語

| 用語 | 意味 |
| --- | --- |
| 端末のキャッシュ | 画面が受け取った API のレスポンスを、端末の IndexedDB に暗号化して置いた写し。つながらない間に読む。期間は受け取ってから 14 日 |
| キャッシュして送る | 取り消せる操作を、先に端末のキャッシュへ映し、つながってから送る扱い |
| 確定待ち | 取り消せない操作を、押した時点のバージョンとともに保存し、つながってからサーバーの今の状態と照合して確定する扱い |
| スキーマの正本 | API の HTTP のルートと形・型などを定義し、ほかの表現を生成する元（`packages/contracts/`）。この課題では API のクライアントの型とダミーデータの元 |
| AI のオーガナイザー | プロジェクトの中で利用者が立て、立てた人の委任で開発を回す AI のエージェント。承認は確定しない。最初の画面（R2）でその一覧と会話を出す |

## ドメインイベント

| # | イベント | 引き金 | 失敗したとき | 順序の前提 |
| --- | --- | --- | --- | --- |
| E1 | 利用者がサインインし、ログインのキャッシュを暗号化して IndexedDB に置いた | 利用者が R1 で Google か GitHub を選んだ | IdP から戻らなければ R1 に留まる。サインインの前に開いていた画面へ戻せなければ `/` へ移る | — |
| E2 | 画面が API のレスポンスを受け、端末のキャッシュへ暗号化して置いた | 画面を開いた・30 秒ごとの読み直し・Web Push を受けた Service Worker からの通知 | 読み直せなければ前の表示を残し「読み直せませんでした（時刻）」を出す | E1 |
| E3 | つながっていない端末で、画面が端末のキャッシュから描いた | 利用者がオフラインで Web アプリを開いた | 端末のキャッシュに無い画面は、つながると読める旨を出す（見せ方は詳細設計） | E2 |
| E4 | つながっていない端末で、利用者が確定待ちの操作を押し、画面が答えの ID を作った | 利用者が承認する・差し戻す・問いに答えるなどを押した | 押してから 24 時間で期限切れにし、もう一度押すよう出す | E2 |
| E5 | 端末がつながり、そろえ方の段 1〜5 を通した | つながった・Web アプリを開いた・画面が見えるようになった | 見られるプロジェクトの一覧を読み切れなければ何も消さず、30 秒後に段 1 からやり直す | E4 |
| E6 | サーバーが確定待ちを今の状態と照らし、確定したか食い違いを返した | E5 の段 2 で確定待ちを送った | 409・403・404 は食い違いを出し、入力した文を残す。503 と通信の失敗は確定待ちに戻して 30 秒ごとに送り直す | E5 |
| E7 | 受け取ってから 14 日を過ぎた端末のキャッシュを捨てた | 画面が端末のキャッシュを読んだ（捨てる時機の細部は詳細設計） | — | E2 |
| E8 | 利用者がサインアウトし、端末のキャッシュとログインのキャッシュを消した | 利用者がサインアウトを押した | 確定待ちがあれば、捨てる前に数を確かめる | E1 |

## 境界
