## タスク分解

変更の種類は機能追加なので、最初に今の振る舞いを縛る退行テスト（確認の値だけが違う `deploy` が止まること）を置く。

### Task 1: 確認の値だけが違う deploy が止まるテストを足す

- **対象ファイル:** `infra/test/nd-setup.test.ts`
- **変更内容:** 上の「修正対象」のテストを 1 件足す。値は作り物の値（`acme-test`・`123456789012`・`us-west-2`）だけを使う。合成の結果とアカウントは `diff` のときと同じにし、`--confirm` だけを変える
- **満たす受け入れ条件:** 6（確認の値の違う `deploy` が止まることの証跡）
- **進め方:** 今のコードの振る舞いを縛るテストなので、書いた時点で通る。確認の値の比較を一時的に外すと落ちることを手元で確かめてから戻す（壊した変更はコミットしない）。範囲のテストは `infra` のテストだけを打つ

### Task 2: 確定仕様の「運用」の手順を直す

- **対象ファイル:** `docs/specifications/app-stack-infrastructure.md`
- **変更内容:** 設計書の「手順の直し」の節の 5 か所（節の冒頭の戻しの予行の文・M1・M2・M4・M5 の行）を直す。どこから読んでも、戻す前に今のスタックとの差分を承認する手順になるようにする
- **書き足すこと（設計承認ゲートの r3-2。オーガナイザーの回答で詳細設計と実装計画へ書き足すと決めた）:** M4 の目印の項目について、(a) 目印の削除を、通常の片付けとやり直しの順の両方で、人が対象の表・鍵・目印の値を確かめて承認する工程として書く、(b) 予行ごとに新しく決める値を属性 `run` として目印に持たせる、(c) `delete-item` に `note` と `run` が今回（やり直しでは前回）の目印と一致する条件を付け、条件で失敗したら消さずに止める
- **満たす受け入れ条件:** 6・7 の前提（結果の記入は Task 5・6）
- **進め方:** 文書の直しのためテスト駆動を適用しない。設計書の「テスト設計」の 6 の行の「節の冒頭に前の合成の結果を反映し直す戻しが残る」に当たらないことを読む

### Task 3: #13 に新しい案内を書き、旧い案内から移れるようにする

- **対象ファイル:** 無し（#13 のコメント）
- **変更内容:** 設計書の「手順の直し」の節のとおり、#13 に新しい案内のコメントを書き、2026-11-21 のコメント（[#13 のコメント](https://github.com/devbasex/nd-factory/issues/13#issuecomment-7069916588)）の先頭に、差し替えたことと新しい案内へのリンクを足す。M2 で使う列ごと・費目ごとの課金の対象の量を案内に書く。確認の値・端末の出力・画面の写しを求めない
- **満たす受け入れ条件:** 6・7 の前提（利用者が新しい手順で確認を行うため）
- **進め方:** コメントの本文に実際の値（12 桁の数字・ARN・リージョンの名前）が無いことを読んでから投稿する

### Task 4: 利用者の報告を待つ

- **対象ファイル:** 無し
- **変更内容:** M1・M2・M4 の 3 つすべてについて、利用者から結果か保留の報告が返るまで、単位 2 を始めない。M5 は待たない。#105 の取り込みも待つ
- **満たす受け入れ条件:** 無し（単位 2 の着手の条件）

### Task 5: 確定仕様の「運用」に結果の表を足す

- **対象ファイル:** `docs/specifications/app-stack-infrastructure.md`
- **変更内容:** 確認の表の直後に結果の表を足す。行は確認ごと、列は実施日・結果（合格 / 不合格 / 保留）・読んだもの・結果を返した #13 のコメントへのリンクにする。M4・M5 は差分ごとに承認したかどうかと日付を書く。M4 を途中で止めたときは、行った工程・止めた理由・行わなかった工程を添える。M5 が返っていなければ「未確認」と書く
- **満たす受け入れ条件:** 6・7
- **進め方:** 文書の直しのためテスト駆動を適用しない。設計書の「テスト設計」の 6・7・値の混入の行に照らす。M5 を「未確認」と書いたときは、同じときに範囲外の課題「確定仕様の M5 の結果を書き入れる」を 1 件起票し、#13 の新しい案内の M5 の行と #13 のコメントで報告先を移したことを知らせる

### Task 6: 全体の設計の費用の見込みを直す

- **対象ファイル:** `docs/design/platform.md`
- **変更内容:** 設計書の「どこを変えるか」の 3 か所（「見込み」の表・「読み方」の段落・「未確認のまま残ること」の表）を、決定 2 の直し方と、M1・M2 の結果（保留を含む）ごとの扱いのとおりに直す
- **満たす受け入れ条件:** 7
- **進め方:** 文書の直しのためテスト駆動を適用しない。設計書の「テスト設計」の 7 と値の混入の行に照らす。要求の「検証手段」の `grep` とリージョンの名前の形の検索を、直した 2 本に打つ
