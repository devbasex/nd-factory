## 種類

機能追加（設置のコマンドとアプリのスタック（`app`）は骨組みとして既にあり、そこへネットワーク・進行表の DB・ECS のクラスタ・予算と知らせを足す）

## 今の姿

アプリのスタック（`infra/lib/app-stack.ts`）は、利用者プール・画面の配信・API の関数 1 本・利用者の表だけを持つ。ネットワーク・進行表の DB・ECS・予算と運用の知らせは無い。設定のファイル（[docs/operations/settings.md](https://github.com/devbasex/nd-factory/blob/main/docs/operations/settings.md)）は接頭辞・環境・ログインの IdP・反映のパイプラインのキーだけを持つ。全体の設計は、足す資源の形を [プラットフォームの文書のインフラ](https://github.com/devbasex/nd-factory/blob/main/docs/design/platform.md#インフラ) と [費用](https://github.com/devbasex/nd-factory/blob/main/docs/design/platform.md#費用) に、進行表の DB の用意を [データの文書の進行表の DB](https://github.com/devbasex/nd-factory/blob/main/docs/design/data.md#進行表の-db) に決めている。

## 何を足すか・変えるか

| | 今 | 足した後 |
| --- | --- | --- |
| ネットワーク | 無い | 自前の VPC（2 つの AZ に公開のサブネットと出口の無いサブネット）。NAT は置かない |
| 進行表の DB | 無い | Aurora Serverless v2（PostgreSQL・最小 0 ACU・書き手 1 台・Data API を有効）と、プロジェクトごとのデータベースと役割を RDS Data API で作る DB の用意の関数（Lambda） |
| ECS のクラスタ | 無い | ECS のクラスタ（サービスとタスクセットを作らない）・タスクの SG（受け入れなし）・権限の文を持たないタスクの役割 |
| イメージ | CDK のアセットとして作る（全体の設計の決定 87） | 自前の ECR へ push してテンプレートがダイジェストで引く形に全体の設計を直す。DB の用意のイメージは無くなり、イメージを持つのはランナーだけのため、作るのは #6（下の「要求から変えたこと」） |
| 費用の見張り | 無い | AWS Budgets の月の予算と、運用の知らせの SNS のトピック |
| 設定のファイル | 4 つのキー | ネットワークの CIDR・最大 ACU・予算・運用の知らせの宛先のキーを足し、ほかの子が読むキーの名前と形を決める |
| `diff` の出力 | 差分と確認の値 | 足りない設定の一覧の欄を足す（終了コードは足さない） |
| スタックのテスト | 名前・タグ・時間で費用が掛かる資源 | NAT・受け入れの規則・VPC の中の Lambda・ECS のサービス・タスクの役割の許可の文・Aurora の最小・消せる設定・PITR の欠けを落とす行を足す |

## 要求から変えたこと

| 日付 | 誰の決定 | 変えたこと | 理由 |
| --- | --- | --- | --- |
| 2026-11-21 | 利用者 | ランナーと DB の用意のイメージを CDK のアセットにせず、設置のコマンドと反映のパイプラインが作って自前の ECR へ push し、テンプレートがダイジェストで引く（全体の設計の決定 87 を直す）。ECR の残す数は、戻したい版の数より十分多めにしてこの課題が決める | CDK のアセットのイメージは自前の ECR に置けず、自前の ECR のライフサイクルの規則で古い版を消せない。ダイジェストで引けば、中身が変わればテンプレートが変わり、確認の値で縛れる |
| 2026-11-21 | 利用者 | 全体の設計（`docs/design/platform.md` の決定 87・ECR の行・LIB85・費用の見込みの ECR の行・設置の段の表・ランナーのイメージの前提・未確認のまま残ること）の直しを、この課題の設計 Pull Request に含める | 上の変更を全体の設計へ返さないと、#6 のランナーのイメージが古い答えを読む |
| 2026-11-21 | 設計者（設計承認ゲートで確かめる） | 実測のうち進行表の DB へ接続する項目（再開の待ち・カタログの分け方・差し替えの排他・DBOS と Aurora の版・ACU の平均・Data API の振る舞い）を #44 へ分けた | DB の用意の関数を呼ぶ側と終わりの記録の口は #6 が作り、この課題のスプリントの中では Aurora へ着けない（1 子は 1 スプリントの決まり）|
| 2026-11-21 | 設計者（利用者の方針「より堅牢で長期的に良い方を選ぶ」による。設計承認ゲートで確かめる） | DB の用意を ECS のタスクから RDS Data API を使う Lambda（DB の用意の関数）に移し、全体の設計（`platform.md`・`data.md`・`api.md`・`overview.md`・`detail.md`）を直した。DB の用意の 2 つの HTTP の経路は無くなった。イメージを持つのがランナーだけになったため、自前の ECR とイメージの push の仕組みは #6 が作る（#6 の本文へ渡した） | 動く部品（タスク・イメージ・引き換えの token・タスクの停止を読む手順）が減り、VPC の外から同じ SQL を打てる（MVV 版 2 の Value 15・16） |

## なぜ困るか

ホステッドのレーン（#6）と DB の用意は、ネットワーク・進行表の DB・ECS のクラスタが無いと動かない。費用の見張りが無いと、自分で設置した人が使わない月の費用の増えに気づけない。全体の設計の費用の見込みは実測していないため、見込みの誤りが設置する人へそのまま届く。

## 目的

| MVV の項目 | この課題で受けること |
| --- | --- |
| Value 6 自前の構成で安く | 他の資源に相乗りせず、NAT を立てず、常駐する計算を持たない構成で、使わない間の費用を 0 に近づける |
| Value 8 承認した範囲だけ反映 | 資源をアプリのスタックへまとめ、同じ確認の値と要約値で縛る |
| Value 7 公開を前提に値を置かない | CIDR・最大 ACU・予算などの値を設定のファイルから受け、リポジトリに実際の値を置かない |
| Vision（誰でも自分の AWS へ安く設置できる） | 予算と知らせで費用を見張り、実測で費用の見込みを確かめる |

機能一覧の行は持たない（F1〜F22 を支える仕組み）。受け持つ不変条件は I10・I11 である。

| # | 中身 |
| --- | --- |
| I10 | 進行表の DB は、プロジェクトごとに別のデータベースとログインの役割を持つ。他のプロジェクトの DB の資格情報を渡す手段を作らない |
| I11 | レーンのコンテナは AWS の権限を持たず、レーンの token はレーンが動く間だけ有効 |

## 対象範囲

含む:

- 自前の VPC（NAT なし・Lambda は VPC の外・Fargate は公開のサブネットで公開 IP、受け入れは空）
- Aurora Serverless v2（進行表の DB。最小 0 ACU・Data API を有効）と、DB の用意の関数（SQL の手順と CDK の関数。呼ぶ側と終わりの記録の口と見回りは #6）
- ECS のクラスタ（サービスとタスクセットを作らない）
- ~~イメージの作り方と置き場（自前の ECR への push・ダイジェストで引く・ライフサイクルの規則）~~ → #6 へ移した（2026-11-21。イメージを持つのがランナーだけになった）。全体の設計の直しはこの課題に残す
- 予算と運用の知らせ（SNS のトピック）
- スタックのテストに足す行: NAT が 1 件以上・タスクの SG に受け入れの規則・Lambda が VPC の中・`AWS::ECS::Service` か `TaskSet` が 1 件以上・タスクの役割に許可の文・Aurora の最小が 0 でない・表とバケットが消せる設定・PITR が無い
- 足りない設定の一覧を `diff` の出力の 1 欄に出す（終了コードは足さない）
- 設定のファイルのキー（予算・最大 ACU・運用の知らせの宛先・設置全体の同時のレーンの数・差し替えの起こし直しの上限・承認資料と操作の記録の保存期間）の名前と形。読み手がこの課題に無いキーは、名前と形と既定だけを決め、形の正本へは読み手の子が足す
- ~~DB の用意のタスク向けの 2 つの HTTP の経路の要求と応答の項目~~ → 経路が無くなり、DB の用意の関数を呼ぶ値と終わりの結果の形に替えた（2026-11-21）。差し替えの起こし直し（I22）の見回りの値と上限の回数は残す
- ~~ランナーのイメージの前提（設置の前提の表とパイプラインのスタックを直してから、イメージを引くアプリのスタックを起点のブランチへ入れる）~~ → #6 へ移した（2026-11-21）
- 実測（接続の無い間の Aurora の一時停止・保守で起きる回数・単価）と、戻しの予行 1 回。接続する項目は #44
- 全体の設計の直し（`platform.md` の決定 87・ECR の行・LIB85・費用の見込みの ECR の行・設置の段の表・ランナーのイメージの前提・未確認のまま残ること）

含まない:

- ランナーのイメージの中身と、進行表の DB の用意の手順の細部（#6）
- サービスの表の列と索引の細部（#2）
- 進行表の DB へ接続して確かめる実測（#44）

## 前提

- 前提 1: 全体の設計の決め直しは「要求から変えたこと」の 2 件（イメージの置き場（決定 87）と DB の用意を Data API の関数へ移す直し（決定 83・90・95・96））だけである。前者は利用者が 2026-11-21 に承認し、後者は利用者の方針（より堅牢で長期的に良い方を選ぶ、2026-11-21）による
- 前提 2: 設計の段では AWS に触れない。実測と戻しの予行は、リリース承認ゲートの承認の後に、反映した環境で行う
- 前提 3: 1 つの子は 1 つのスプリントで閉じる大きさにする（plan.md の決まり）。超えると分かったら、詳細設計で子を分けて本文を直す

## 非機能の条件

| 大項目 | 条件 |
| --- | --- |
| 可用性 | 表とバケットと Aurora のクラスタは、スタックから消しても残る（ECS のクラスタは状態を持たないため対象にしない）。戻しの予行を 1 回行う |
| 運用・保守性 | 予算の知らせと運用の知らせが、設定のファイルの宛先へ届く |
| セキュリティ | タスクの役割は権限の文を持たない。タスクの SG は受け入れを持たない。合成の出力に秘密の値を持たない |
| システム環境 | 合成は資格情報なしで通る（lookup を使わない） |

## 影響

| 対象 | 影響 |
| --- | --- |
| 公開インタフェース | 設定のファイルにキーが増える（どれも任意で既定を持つ。今の設定のファイルはそのまま読める）。`diff` の出力に欄が増える |
| データ | 進行表の DB を新しく作る。サービスの表の形は変えない |
| 既存の振る舞い | 変わらない（イメージの push と Docker の前提は #6） |

## ドメインイベント

| # | イベント | 引き金 | 失敗したとき | 順序の前提 |
| --- | --- | --- | --- | --- |
| E1 | 設置する人が `diff` で差分・確認の値・足りない設定の一覧を読んだ | 設置する人が `diff` を打った | 設定のファイルが形に合わなければ 1 件 1 行で示して止まる（終了コード 2・3） | — |
| E2 | アプリのスタックを反映した（ネットワーク・進行表の DB・ECS のクラスタ・DB の用意の関数・予算） | `deploy`、または反映のパイプラインの承認 | 確認の値が違えば反映しない。反映の途中の失敗は CloudFormation が戻す | E1 |
| E3 | DB の用意の関数がプロジェクトのデータベースと役割を作った | API の非同期の呼び出し（最初のホステッドのレーン。呼ぶ側は #6） | 作成の時間切れで見回りが用意の ID を条件に `無い` へ戻す（I18） | E2 |
| E5 | 実測と戻しの予行を記録した | リリース承認ゲートの後の反映 | 実測が見込みと外れたら、全体の設計の費用の見込みと詳細設計を直す | E2（E3 を前提にする接続の実測は #44） |

## 検証手段

| 項目 | 手段 |
| --- | --- |
| テスト | CI の `check`（`npm run check`: lint・型検査・生成物の差・単体テストとスタックのテスト）と `synth`。このリポジトリはテストを CI に寄せる（`.ndf/project.json` の `test.ci.only`） |

| 値の混入 | `grep -nE '(^\|[^0-9-])[0-9]{12}([^0-9-]\|$)\|arn:aws' docs/design/platform.md docs/specifications/app-stack-infrastructure.md docs/specifications/db-prep-function.md` が作り物の値 `123456789012` 以外に当たらない |
| 手動確認 | 接続しない実測（接続の無い間の一時停止・保守で起きる回数・単価）と戻しの予行。反映した環境で行い、結果を詳細設計と全体の設計へ返す。接続する実測は #44 |
| 手動確認（マージ前） | 設計承認ゲートで、承認する人が全体の設計の直し（決定 87 のイメージの置き場と、DB の用意を Data API の関数へ移す直し）を読む |
